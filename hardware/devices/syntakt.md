## SY FM4 facts (README, Syntakt OS 1.40A)
Replaces SY TONE in place on the digital tracks: ALGO 0 is SY TONE itself (sample-identical to the stock machine, so existing projects sound the same), ALGO 1-8 the classic Yamaha 4-op set, ALGO 9-11 tree, diamond, ring; the second parameter page SYN 2/2 adds operator-3 (ALGO, RAT3, LEV3, DEC3) and operator-4 (DET, RAT4, LEV4, DEC4) controls, DET detunes operators 2-4 by +/-16 semitones; page 2/2 is saved with the sound and p-lockable (sounds saved by stock open with page 2/2 at SY TONE defaults). Patchers read the user's own OS and check the SHA-256 of each byte range they overwrite. **Hardware:** tested on a real Syntakt 1.40A - installs, all parameters including p-locks work, an 8-track load test ran 47 s without audible clicks, dropouts or clipping; sound/pattern-lock save-reload and CPU cost were only checked in an emulator (digiemu with a Syntakt port). **CPU:** ~8.9k cycles per voice per block vs 7.2k-9.8k for stock engines; 8 SY FM4 voices ~66 % voice CPU. **Limits:** section 7 has a size limit (`0x60000 - 5` bytes in 1.40A); page 2/2 reuses descriptors 1-5 and 12-14, which were MIDI-CC placeholders in 1.40A and are removed. Porting to 1.41/1.42 means remapping every 1.40A address and rechecking the section 7 limit, main OS layout and the placeholders. `[hw]/[emu]` {syfm4-readme}

## Facts
- Only OS **1.41** is targeted (Synthack-OS "Syntakt MAX", SY FM4 builder; syntakt-firmware-workbench refuses other files). A user asked on 2026-10-01 for Modded-Cycles' flasher to accept Syntakt OS 1.42; support is not confirmed. `[doc]` {synthack-os} {syntakt-workbench} {modded-cycles-thread}
- Mod code lives in a **64 KB RAM area**, stored compressed and unpacked at boot. `[doc]` {synthack-os}
- Each Synthack mod is a `patch.json` (target location, hash of expected original bytes, replacement bytes). `build.py` combines the stock OS with chosen mods into a `.syx`, refusing a wrong OS, overlapping patches and protected sections. Firmware is unpacked/repacked with a wrapper around elektron-firmware-tool. `[doc]` {synthack-os}
- Install: Elektron Transfer over USB (Drop page); revert by flashing the stock OS the same way. Read the author's `RECOVERY.md` first (not yet read by us). `[doc]` {synthack-os}
- Planned custom engines (RISER/DOWNFILTER, SY SWARM+) would need custom audio-engine code on "CPU #2". `[doc]` {synthack-os}
- Syntakt engines can be extracted from Syntakt OS 1.41 and loaded into Model:Cycles (Modded-Cycles needs a Syntakt_OS1.41.syx). `[doc]` {modded-cycles-thread}
- Forum claim: the Syntakt board resembles the original Digitone minus analog parts, with two ColdFires and an FPGA in similar positions. `[?]` {elektronauts-dn2-pcb}
- Status: Synthack-OS reports seven mods running on real hardware (v0.8.0); each is tested in the emulator against the original code before flashing. `[hw]` {synthack-os}

## Recovery (SyntHack OS `RECOVERY.md`)
Normal case: Drop page in Transfer. If the OS does not boot: DIN MIDI, FUNC at power-on, TRIG 4, SYSEX TRANSFER "OS Upgrade via device startup menu", tens of minutes at 31.25 kbit/s; **avoid TRIG 2 and TRIG 3 (erase data)**; do a dry run with stock first; only flash files whose `eft.py info` shows `checksums : ok`. No hardware results reported on that page. `[doc]` {synthack-recovery}
- **Mod data written for defaults slows project load and save (Synfact, OS 1.41):** a user saw a project load slowly when switched to from another project and save more slowly than usual; a reboot straight into it loaded normally. The export was valid. The ARP mod wrote and sealed a 320-byte carrier for every kit even with default settings, so load checked all 1,664 bindings; leaving default carriers absent cut the emulated serialization from 24.8 M to 4.8 M instructions (81 % fewer). The slowness is a user report; the cost is `[emu]`, the wall-clock gain not yet measured. `[doc]` {synfact-lifecycle} ([I50](../INCIDENTS.md#i50-mod-data-written-for-default-settings-slowed-project-load-and-save))
- **Tested on a unit (Modwerk, 2026-11-04, OS 1.42):** the startup-menu recovery works over MIDI DIN through a generic USB-to-MIDI cable: FUNC at power-on, TRIG 4 (OS UPGRADE), stock 1.42 sent from Transfer's legacy SysEx page; the unit booted and showed 1.42. This run recovered a working unit; recovery of a unit that does not boot is still untested. USB does not work for this path. `[hw]` {modwerk-st-probe} ([I46](../INCIDENTS.md#i46-syntakt-startup-menu-recovery-tested-over-din))
- **A modified 1.42 image boots and runs (same run):** Modwerk's boot probe (version shown `MW01`, flashed over USB with Transfer) booted to the live UI, played a stock project, came back after two power cycles, held every sample slot filled with no hang or exception screen, and played ten minutes cleanly; flashing stock 1.42 over USB restored the unit. Not tested: OS 1.40, the probe under Outbox 8, an SRAM-tail signature. `[hw]` {modwerk-st-probe}

## Syntakt OS 1.41 static-analysis facts (Humgic/syntakt-machine45-research - README {machine45} and handoff dated 2026-10-28; no hardware run, no firmware)
- Address rule `VA = file offset + 0x40000400`; ColdFire big-endian (ISA-C/EMAC). MAIN is 3,438,480 bytes, section 7 is 383,760 bytes. `[doc]` {machine45-handoff}
- **Stock public Machine IDs are 0-44**, stored as a BYTE in each track's machine payload (`P[t]+0xA2`); runtime records `R[t] = model + 0x6C + 0x3C0*t`, `P[t] = *(R[t]+0x10)`; the setter is at `0x40025594` (store at `0x40025620`). 505 parameter descriptors of 52 bytes; only MAIN digital tracks 0-7. `[doc]` {machine45-handoff}
- Section 7 selector: a signed BYTE with a 46-entry map (negative -> 0, 0-45 kept, above 45 clamped to 45); stock maps 0-7 to the same-numbered engine family and 36->8, 37->9, 38->10, 44->11, everything else (incl. 45) to family 0. Stock tables: render pointers `0x400148F0` (12 entries), prep pointers `0x40014920`, the 46-byte map at `0x40014950`. A compact handoff moves MAIN `[0x80002000,0x800021B0)` through a 27x16-byte eDMA transfer (TCD47, channel 47); each track then receives a 20-byte copy into `T[t] = 0x80003C40 + 0x8E*t`. Dslot is 8 x `0x708` = 14,400 bytes. `[doc]` {machine45-handoff}
- Persistence confirmed statically: the current-kit Sound-v7 save/load keeps the machine byte (raw 0-45 and 255 retained, 46-254 map to 0); Pattern-v11 stores the byte at row `+0x2EC` and its restoration is **not closed**; Sound locks, p-locks, held trigs, migration, clipboard and undo not qualified. Evidence labels in that repo: confirmed by static analysis / verified in emulator (none for the whole device) / verified on hardware (none) / hypothesis. `[doc]` {machine45-handoff}
- Open: safe executable storage for native DSP on "CPU 2" (the loader boundary is unresolved); composition with SY FM4 (engine 4, A-table entry overlap) and other descriptor mods; resource IDs 254-261 are unclaimed in the registry but have MIDI CCs, 505+ have no native allocation. `[doc]` {machine45-handoff}

## Platform: two ColdFires, an FPGA, an analog mixer (SyntHack OS docs, OS 1.41) {synthack-docs}
- **Two ColdFire MCF5441x** (V4, EMAC, **no FPU**, ~250 MHz, so **166,667 cycles per 32-sample block**), with 64 KB SRAM at `0x80000000`. RAM shared between the CPUs is at `0x10000000`. `[doc]`
- **Sections of OS 1.41**, stored in the order 5, 2, 1, 3, 4, 6, 7, 8:
  | Section | Content | Size | Note |
  |---|---|---|---|
  | 1 | FPGA bitstream | 149,516 B | never touch |
  | 2 | bootstrap with the STARTUP menu | 30,782 B | never touch |
  | 3 | MAIN OS for CPU #1, at `0x40000400` | 3,438,480 B | patched by mods |
  | 4 | updater | 32,776 B | raw; never touch |
  | 5 | meta | | |
  | 6 | ColdFire boot stub | 1,744 B | raw; never touch |
  | 7 | **voice engine for CPU #2**, at `0x40000400`, entry `0x40001070` | 383,760 B | raw; patchable |
  | 8 | the shared ARM Cortex-M image (not a second FPGA; CONFLICTS S15) | 159,948 B | identical in size to the DT1/DN2/Rytm/A4 image whose hash is known |

  Stock 1.41 SHA-256: `8e2488f4...b9ed19e`.
- **Signing conflict `[?]`:** SyntHack describes an HMAC-SHA256 over the container for 1.41, with the key derived from the image. digikit found no HMAC trailer in 1.42 (the last 32 bytes are zero). Check the trailer of your own file before you decide.
- **Boot unpack limit:** the bootstrap loads compressed section 3 at `0x40200000` and unpacks it to `0x40000400`. The margin (decompressed minus compressed) must stay below ~`0x1FFC00` at every point of the stream.
  - Stock 1.41 has a margin of +99,938 B.
  - A build padded with zeros to `0x40350000` (-8,751 B) **did not boot, tested twice** and hung on the logo.
  - Zero padding is the worst case; already-compressed payloads raise the margin. SyntHack refuses builds under 4 KB of margin. `[hw]`
- The Syntakt accepts rebuilt images (recompressed section 3) over USB and DIN. `[hw]`

## Memory map of CPU #1 (OS 1.41) {synthack-docs}
| Range | What |
|---|---|
| `0x40000400-0x40347B90` | section 3 image |
| `0x40338740-0x40339000` | linker fill, **free** (used by SyntHack's splash, dual-mono and loader; nearly full) |
| `0x40339000-0x45565490` | BSS, zeroed at boot (`0x400004B2`, called once) |
| `0x444E38C0-0x454E38C0` | OS heap (buddy allocator `0x4010350C`, free `0x40103712`, 16 MB, 16-byte units). The first 64 KB block is SyntHack's **mod area** |
| `0x45565490-0x48000000` | **no code reference, but the OS writes all over it when it loads samples**; the stock sample blob fills it from `0x4584f2c5` (up to `0x4759b3c5` with all 64 slots full), see the Synfact findings of 2026-11-17 {synfact-1118} |
| `0x48000000` | boot stack top |
| `0x4D570000`, `0x4FC00000` | delay and reverb lines |
| `0x80000000-0x8000FFFF` | SRAM: audio buffers, DMA rings, engine parameter arrays |
| `0x10000000` | RAM shared with CPU #2 |
- **Hardware lesson `[hw]`:** SyntHack up to v0.8.0 kept mod code at `0x46000000`. Projects with SP TWINSHOT samples then crashed at boot. Since v0.8.1 the mod code (compressed, appended to section 3 at `0x40348000`) is unpacked into a 64 KB block that a hook at the end of heap init (`0x4010358E`) reserves first. ([I20](../INCIDENTS.md#i20-mod-code-at-a-free-address-crashed-projects-with-certain-samples))
- **Conflict to watch `[?]`:** SY FM4 (OS 1.40A) copies its code to `0x47000000`, which it describes as "above the BSS end, below the stack, addressed by nothing". That is the region SyntHack found to be overwritten by sample loading on 1.41. Treat any use of RAM above the BSS as unsafe until it is tested with sample-heavy projects. Synfact's reading (2026-11-17) puts `0x47000000` inside the stock sample blob's span (`0x4584f2c5-0x4759b3c5` with all 64 slots full). `[emu]` {synfact-1118}
- Boot: entry `0x400004E8`; static constructors loop `0x40082500` (136 entries); the intro animation task `0x40087E6A` gates boot, so **never make the intro longer**. Screen: 128x64 1 bpp, column-major, double buffer at `0x402D6DC4`/`0x402D6DC0`; frame loop `0x4000A0E6` redraws when `*(0x444E1334)+96` is set. `[doc]`

## Audio path {synthack-docs}
- **CPU #2 (section 7):** all work runs in the audio interrupt `0x40000934` (vector 96, DMA timer 0 capture).
  - Per block it copies `0x1B0` bytes of parameters from shared RAM and renders **8 digital voices** (`0x40004324`).
  - It returns 8 x 32 int32 over eDMA channel 47 and does no mixing.
  - 12 engines: tables at `0x400148F0` (render), `0x40014920` (update), `0x40014950` (machine id -> engine). Order: BD MODERN, SD BASIC, CY ALLOY, PC CARBON, SY TONE, SY CHORD, SD VINTAGE, CP VINTAGE, SY TOY, SY BITS, SY SWARM, SP TWINSHOT. SY CHORD reads a 512 x int32 wave at `0x4001A300`. `[doc]`
- **CPU #1 (section 3):** the per-block routine `0x400A3856` runs CV/gain, ADC deinterleave, then master/FX `0x4008F1CA`. Delay `0x40096890` and reverb `0x40096E3C` are the same code as on the Digitakt mk1.
  - Buffers: digital tracks from CPU #2 at `0x80003D50`. ADC channels at `0x80003950`: 0-3 analog tracks, 4-5 external in, 6-7 the FX-track bus.
  - USB/Overbridge: 20 channels per frame at `0x80004760`.
  - **The final mix is analog:** digital buses go out through DACs into an analog mixer, with nothing digital after them. 40 control voltages go out over DSPI1 with eDMA channel 15; CV 35/36 are the FX-track bus VCAs. `[doc]`
- **CPU #1 load: ~89 % at rest** (sequencer stopped), measured on the device with DTIM0 (`0xFC07000C`) at interrupt entry and exit. The UI gets the rest, so **a few thousand instructions per block make the UI lag**. `[hw]`
  - SY FM4 reports its main-CPU render at 85.8k of 166.7k cycles per block (stock 85.0k). That is a different span of the same interrupt. `[?]`
- Digital filter and amp run on CPU #2; the cutoff is computed on CPU #1. Analog voices and the FX track drive a **hardware envelope generator** with 20-bit rate codes. Measured curves: the digital biquad f0 = 4.918 Hz x e^(0.0655 x FREQ); the analog filter f = 14.645 Hz x e^(0.0574 x FREQ). Tempo is at `0x402D7010` (BPM x 120). `[hw]` (analog curves measured)

## CPU #2 (the voice CPU, section 7) - memory map from SynCrackd (OS 1.41 and 1.42) {syncrackd-mm} `[doc]`
- **Section 7 is byte-identical in 1.41 and 1.42** (SHA-256 `daf6451c...783bc2`). It is ColdFire ISA-C with EMAC, MCF5441x-class: compile with `-mcpu=54418`, disassemble with `-m m68k:isa-c:emac`. CPU #2 has **its own 128 MB SDRAM** at `0x40000000` (SP `0x48000000`, entry `0x40001070`). `[doc]`
- **Only 39.8 KB is code** (`0x40000404-0x40009f88`: boot, audio interrupt, voice loop, 12 engines, sample loader), followed by 284 KB of tables and data. Code room for mods is almost nil: ~318 bytes in small pieces remained after SynCrackd's images.
- **CPU #2 configures its own FPGA:** a packed bitstream at `0x40041060` is unpacked to `0x40042000` (54,664 bytes) at init. That is the same size as the Analog Heat +FX FPGA section, so it may be the same part `[?]`. Keep away from it (rule A22).
- **The sample pool is in CPU #2's RAM:** 64 MB from `0x4004f750`, in BSS zeroed at boot. A 64-entry slot table `{u32 frames, u32 pointer}` is at `0x4404f754`.
  - Format: 64 times `u32 frames` + big-endian int16 mono.
  - The main CPU fills it at boot in 2 KB chunks through the shared window `0x800`, with an unchecked 16-bit index. This is the slow boot the manual mentions.
  - Per slot at most 524,287 frames (10.9 s; positions are 20.12 fixed point). The stock UI limits slots to 5 s and "32 MB".
- **Above the BSS, `0x4404f980-0x48000000` (63.7 MB) is not referenced by any section-7 instruction** and is used for SynCrackd's state. Leave the top megabyte for the stack (its depth is not measured). This is CPU #2's RAM, not the main CPU's region that sample loading overwrites (CONFLICTS O2). `[hw]` (alpha, one unit)
- **Shared window** (CPU #2 `0x0-0x1000` = main CPU `0x10000000`, chip select 0, 16-bit, one wait state):
  - `0x000-0x1b0`: the parameter block, copied to `0x80008000` every block;
  - `0x1b0-0x5b0`: 8 mono track buffers, sent by eDMA 47;
  - `0x5b0-0x800`: unused by stock;
  - `0x800-0x1000`: the sample chunk at boot.
- SRAM `0x80000000`: 8 voices of 1,800 B, 8 mono int32 output buffers, 8 parameter blocks of 142 B. The highest static reference is `0x8000f670`, so treat SRAM as full.
- **Twinshot (engine 11, machine type 44)** reads the parameter slots 18-25: TUN1, SMP1, FLT1, MIX, TUN2, SMP2, loop flag, DEC1. **A sample select below the centre plays the slot in reverse.** `[emu]`
- SynCrackd replaces Twinshot (and CY ALLOY) with a 64-slot stereo sampler, loops, slices, time stretch and transient triggers. It is OS 1.42 only, alpha, tested in emulation and on one unit, MIT.
- Synfact (OS 1.41; source builds on 1.42 from core 2.0, 2026-11-17) adds DT mk1 sample machines, a per-project pool, polyphony across tracks and a third LFO.
  - It ships its firmware change as a **zlib-compressed XOR mask** against the official file, pinned by hash.
  - It needs a second mods file (515,808 B) sent with its own transfer tool after the flash. Boot is confirmed on a unit (core 1.4 and 1.7.2, 2026-11-09); the safe-boot rollback is not yet tested on hardware. `[hw]` {synfact} {synfact-core}

## How mods are built on the Syntakt (SyntHack modding guide, worth copying) {synthack-guide} `[doc]`
- **Each change is stored with the SHA-256 of the original bytes**, so a different OS version fails the build instead of crashing. Every mod runs in a Unicorn emulator next to the original code before flashing.
  - **Stock Unicorn gets signed fractional EMAC wrong** (the audio comes out silent), so EMAC instructions are trapped and executed in Python from the NXP manual.
  - Use CPU model "ANY" (the code needs FF1, MVS/MVZ, SATS).
- Hooks: replace at least 6 bytes with `jsr` plus `nop` padding, and the trampoline replays the replaced instructions.
  - Save every register; replay replaced EMAC instructions first.
  - If your code uses EMAC, set MACSR yourself and **leave ACC0 at 0**, because the OS sum routines start from it.
  - One-time setup goes in a hook in the page initializer (`0x401885D2...`), never in boot time.
- Mod code: gcc/as with `-mcpu=54418`, no `.bss` (put variables in `.data`), no libgcc (`nm -u` empty).
  - ColdFire limits: `muls.l` takes no absolute address, there is no `exg`, `movem` takes only `(An)`/`d16(An)`, short branches reach ±127 B.
- **Spare storage the OS saves without knowing:**
  - per track: engine word +106 (hidden id 72);
  - per kit: unused words of the pattern kit at `*0x800030BC` (ids 0, 0x1A, 0x24, 0x27, 0x29, 0x2A, 0x37, 0x46, 0x38). Store values XOR their default, so old projects load with defaults;
  - kit words 41-43 of the 12 per-track kit blocks (Digitakt MIDI-track data, unused here);
  - 256 bytes in the project settings file.
  - A "free" parameter id can be an alias the OS shows in some modes, so audit it.
- UI internals: parameter descriptors at `0x4022D59C + 52*id`; page objects at `0x41B9F3C8` (44 B, 8 slots); per-parameter `std::function` objects at `0x41B9FA24 + 84*id` (+20 text, +36 icon, +68 style). Page 25 ("OB8") is a free Digitakt leftover. **Rewrite a `std::function` only from UI code, never from the audio interrupt.**
- **Audio mods:**
  - Hook the mix function; keep the OS's EMAC `msac` sign convention (the result is -Σ g·x).
  - Do nothing when there is nothing to do. Compute at 24 kHz where the sound allows it.
  - Ramps must snap to their target or the effect never goes idle.
  - Limit how far a modulated delay moves per block.
  - Keep a cost-per-block regression test (count instructions with `UC_HOOK_CODE` after `ctl_flush_tb()`).
- **Where mod code lives at run time (SyntHack modarea, v0.8.1+):**
  - The OS image has only ~2 KB free, and everything after it is zeroed at boot. So mod code is appended to section 3 compressed (SHLZ, at `0x40348000 + offset`).
  - At boot it is unpacked into the **first 64 KB block of the OS heap**: buddy allocator `0x4010350C`, 16 MB pool at `0x444E38C0`.
  - The block is reserved by a call right after heap initialization, so it always gets index 0, and the OS never hands it out again.
  - The earlier home above the BSS (`0x46000000`) was overwritten whenever samples loaded (SyntHack issue 4), which settles conflict O2. `[hw]` {synthack-mods}
- **Kit and project storage that round-trips through stock code** (SyntHack kitstore/projstore):
  - Kit words 41-43 of the 12 per-track blocks go into 6 file bytes that stock's writer zeroes and its reader ignores.
  - 256 bytes go into the project settings block (`+0x227..+0x3FF` is zeroed by the writer and ignored by the reader), behind an `SH` marker.
  - Tests run the real writer and reader with and without the hooks.
  - Zero must mean "default", because stock-saved files load as zero. `[emu]` {synthack-mods}
- **Controlling the analog side digitally** (SyntHack master-comp): a feed-forward compressor detects on ADC 6/7 (the FX-track bus before its VCAs) and applies gain through those VCAs' control voltages (CV 35/36), once per block (~1.5 kHz). Its UI uses the Digitakt MIDI-track "CC Select" ids 262-268, which the Syntakt never uses. Cost: ~100 instructions per block when off, ~600 when on. Checked on the device (v0.9). `[hw]` {synthack-mods}
- Projects: SyntHack OS (9 mods on hardware, MIT); SY FM4 (4-operator FM replacing SY TONE, which also patches CPU #2); Syntakt Firmware Workbench.
  - The Workbench replaces SY CHORD's waves: 31 slots of 257 big-endian Q31 samples, measured on a unit within 1 %. It adds a Deja Vu LFO, DV-H. It refuses any file but 1.41 and checks that only the declared regions changed. `[hw]` {syntakt-workbench}

## Syntakt OS 1.42 container and CPUs (digikit finding 70, static reading, 2026-10) {digikit-f70} `[doc]`
- `Syntakt_OS1.42.syx`: ELE3, 2,029,486 bytes, META stamp 2026-09-30 (same day as DT2 1.17 and DN2 1.12), SHA-256 `ded3c59f...7f37c1`; SysEx transport id `0x16`, OS-stream byte `0x11`; same packing codec as DT2/DN2; per-packet checksum constant K = 0x11. `[doc]` {digikit-f70}
- **No HMAC trailer - the Syntakt OS file is not signed** (no SHA-256 constants in sections 2-4); only the content checksum applies. `[doc]` {digikit-f70} Correction 2026-11-18: there is no trailer slot at all; the container (2,029,392 bytes, the value in its length word) ends at the end of section 8 rounded up to 16, where DT2/DN2 add 32 bytes, and digikit's rebuild of the stock file matches it byte for byte. `[doc]` {digikit-st-1118}
- Sections: 5 META; 2 bootstrap (dest word `0x04000000`, ColdFire code at `0x8000xxxx`, 30,782 B); **1 present only on Syntakt: `0xFF` padding then a bitstream-like blob (149,516 B) - the FPGA configuration** (~~the bootstrap configures a Xilinx-style FPGA via INIT_B/DONE; MAIN only reads a status word~~ corrected by digikit 2026-11-19: MAIN configures the FPGA from section 1, see the digikit-1121 section below {digikit-1121}); 3 MAIN at `0x40000400` (3,442,576 B, same reset path as DT2: entry `0x400004e8`, SP `0x48000000`); 4 UPDATER at `0x80000400` (32,768 raw); 6 present only on Syntakt (1,744 B; per digikit's newer reading the peer CPU's stage-1 loader, linked at SRAM `0x80000000` {digikit-st-1118}); **7 is not a SHARC stream here but a standalone ColdFire program** linked at `0x40000400` (entry `0x40001070`, 383,760 B) driving a DSPI-like block at `0xFC05C000` - consistent with a second ColdFire that runs the digital machines `[?]`; 8 byte-identical to DT2/DN2's section 8. `[doc]` {digikit-f70}
- **Peer link ("DSP boot"):** a mailbox in the FlexBus window at `0x10000000` ("HO" hello / "NO" -> DSP_MEM error; `0xA5A5` at +4 for OK), a doorbell on GPIO PA bit 4, EPORT IRQ4 handshake, 2 KB chunks to `0x10000800`, DSPI2 with eDMA channel 29; status values WAIT, init fail, TIMEOUT, BUFSIZE, DSP_MEM, CF_MEM, OK; the OS shows "DSP BOOT FAILURE (TIMEOUT/CF/DSP/BUF)". ## What the Syntakt shares with other boxes (merged from analog-emu's Syntakt port, OS 1.42, static plus emulator) {analog-emu-syntakt}
- **The analog tracks reuse the Analog Rytm MKII's voice design.**
  - The voice control records have the Rytm MKII's format (command/depth word, start and target bytes, mode nibble, rate exponent and mantissa).
  - The cymbal oscillator banks use the Rytm's scale (43.62 units per Hz) and load the Rytm's CH/CB CLASSIC values.
  - So Rytm voice research applies here and back. `[doc]` (inferred from the shared formats)
- **Digital tracks:** rendered on CPU #2, then handed over by mailbox and eDMA channel 47 to CPU #1, which mixes them and sends them to the SSI1 codec. This agrees with SyntHack's audio path above. `[emu]`
- **An emulator now boots 1.42 with both CPUs** (analog-emu: stage 1 the main screen with a stand-in for CPU #2, stage 2 CPU #2 running for real). It is the only Syntakt 1.42 emulator in the catalogue; SyntHack's Unicorn harness targets 1.41. `[emu]`

## Synfact core and SMZ4 banks (OS 1.41, 2026-11-10) {synfact-core} {synfact-safeboot}
- **Bank store:** two 8 MiB slots inside the old 16 MiB `/mods` reservation, metadata sectors at eMMC `0x02bffe00` and `0x033ffe00`; the legacy record at `0x03400000` is still read. `[doc]`
- **Safe boot:** a bank moves CANDIDATE -> TRYING (written before any bank code runs) -> GOOD, set once AUDIO and the sample pool are ready and 150 UI ticks (about 5 s) have passed; a crash or power-off before that boots the previous GOOD bank or stock machines. Each bank names an exact core contract, and the core checks the stock bytes that LFO3 and MODULATION SKIP patch before any initializer runs. `[doc]`, rollback `[?]` (not yet tested on hardware). The first trial crashed every boot (I62).
- **Filter table:** the stock base-width filter reads Q31 poles from `0x40040060` (508 poles, then a zero tail; indices up to 1023 are read). A mod window in that tail made BASE+WDTH of 128 or more read code as poles; core 1.7.2 bounds the index. `[hw]` (I63)
- **Load:** MAIN is about 88 % with a plain pattern and 91-92 % with three POLY voices; code fetched from DDR costs far more than its instruction count (I64). `[hw]` {synfact-chorus}
- **Load after the MAIN optimisation (owner's unit, OS 1.41, stock pattern, 2026-11-13/14):** a minimal bank (System Info + Modulation Skip) reads 81 % MAIN, the full bank 86 % before and 83 % after the optimisation release; about 2 points sat in LFO3's per-block callback, about 1 in the stereo audio callbacks. - **Appended boot storage is wiped at startup:** on OS 1.41 the storage appended after the MAIN image is cleared and reused once the early resident copy is done, so code placed there is gone when the application runs; only the resident reserve (64 KiB in Synfact's core) is safe for code called after boot (I104). `[hw]` {synfact-main-opt}
- **Stock track types:** every stock digital track type has bit 6 clear; Synfact's machines use types 64-79, so a mod can tell that all tracks are stock from the type bytes alone. ## Synfact findings: stock sample blob, OS 1.42 port (OS 1.41/1.42, 2026-11-17) {synfact-1118} {synfact-os142-1118}
- **Stock builds one sample blob in MAIN DDR at boot:** the native builder (`0x400822bc` on 1.41, `0x40082334` on 1.42) reads each of the 64 stock slots through a temporary 512 KiB buffer and concatenates them at physical `0x4584f2c5` (used through the uncached alias `0x4d84f2c5`; same address on both OS versions): 64 `u32` frame counts, then 2 bytes per mono frame, no 64-byte SAMP header; an empty slot still takes its 4-byte count. With 64 five-second slots it is 30,720,256 bytes (29.30 MiB) and ends at `0x4759b3c5` (exclusive). The stock sender (`0x40082f90` on 1.42) then copies it in 2,048-byte pages through the mailbox at `0x10000800`; CPU #2 keeps its own copy. `[emu]` (Unicorn running each OS's own builder with file and heap stand-ins)
- **So `0x45565490-0x48000000` is unsafe from about `0x4584f2c5` up:** past 8,064,315 bytes of blob (84.000625 s of mono 48 kHz PCM16 in all, for example 17 five-second samples) it reaches `0x46000000`; in the reproduction the first overlapping write came from stock's memcpy (`0x40115f94` on 1.41, `0x40116158` on 1.42) while copying slot 17. This is the mechanism behind SyntHack's lesson at `0x46000000` (I20) and also covers SY FM4's `0x47000000`. Limiting each slot to 5 s does not keep it out. `[emu]` / `[hw]` (I145)
- **CPU #2 reads the stock pool at `0x4004f750`:** its receiver (`0x40000fba`) and descriptor parser (`0x40000d06`) use that base, unchanged from 1.41 to 1.42 (section 7 is identical). Synfact's 1.42 port first moved the base to `0x4004f7c8` by mistake; core 2.0.1 restores it. `[emu]`
- **Stock per-slot limit as Synfact checks it:** one sector per stock header, a SAMP header and at most 240,000 mono frames (5 s); a slot's on-disk body is at most 480,064 bytes (64-byte header plus PCM). All 64 full slots are 15,001 sender pages. `[doc]`
- **Synfact core 2.0.1 streams instead:** it no longer calls the stock builder; it plans the 64 slots from their headers and builds each sender page on demand from eMMC (byte-identical to the old blob), using 5,120 bytes of MAIN scratch freed by a task-only hook at `0x40083026` after the last mailbox copy. Waveform envelopes are read lazily (at most 4,096 PCM bytes per UI idle call); the cache is about 98 KiB for 128 entries, allocated on first use. The native heap is 16 MiB, too small for a 29.3 MiB blob anyway. Resident use: 65,116 of 65,536 bytes (420 free). `[emu]` (sender, page and parser code run in Unicorn); boot with 64 five-second samples `[hw]` (prototype, owner's unit)
- **OS 1.42 versus 1.41 (MAIN):** build id 0097 (1.41: 0094); MAIN decoded 3,442,576 bytes (3,438,480); container 2,029,392 bytes (2,028,880), plus 94 transport-padding bytes in the .syx; SRAM copy source end `0x40348b90` (`0x40347b90`); BSS clear end `0x45566490` (`0x45565490`); boot stack `0x48000000` on both. MAIN SHA-256 `1a9723b1...eb3e7`. Sections 1, 2, 4, 6, 7 and 8 (bootstrap, updater and AUDIO included) are byte-identical; section 5 and the container header change. `[doc]`
- **No single offset from 1.41 to 1.42:** code and tables moved by `+0x78`, `+0xac`, `+0x1c4`, `+0x29c`, `+0x2a0`, `+0x320` or `+0x354`; the DDR image and BSS by `+0x1000`. Synfact found its 108 sites with masked byte-pattern contexts and then checked each one. Examples (1.41 -> 1.42): draw-all `0x401007ce` -> `0x40100992`; operator new `0x40103788` -> `0x4010394c`; menu item ctor `0x400fa688` -> `0x400fa84c`; menu add `0x400f9ebe` -> `0x400fa082`; app startup site `0x400826a6` -> `0x4008271e`; mixer call `0x400a4fce` -> `0x400a5046` (calls `0x4008f1ca` -> `0x4008f242`); modulation `0x40097afc` -> `0x40097b74`; LFO `0x40119266` -> `0x4011942a`; deferred view cleanup's clear `0x40100f2c` -> `0x401010f0`; trig preparation `0x4008b882` -> `0x4008b8fa`. Key and encoder dispatch (`0x4000839e`, `0x400083f0`) and the vector-base routine `0x40001d28` did not move. `[doc]` (G5 anchor data)

## digikit findings: peer CPU, RAM, card, NOR, panel (OS 1.42, static and emulator, 2026-11-18) {digikit-st-1118}
- **How the peer CPU gets its program:** MAIN reads ids 6 and 7 from the OS directory in NOR (`0x80000`, "ELE3", 16-byte entries from `0x80020`: id, offset, length) and streams them **at every boot** over DSPI2 (`0xEC038000`) in **slave** mode, eDMA channel 29 one byte per request. Buffers are `0xAA | big-endian length | payload`: id 6 at `0x4f8af2c1` after eight `0xFF` bytes (MAIN changes byte 1 from `0x01` to `0x0f`), id 7 at `0x4f84f2c1` (length limit `0x5fffb`, matching SY FM4's "0x60000 - 5"). Section 6 (stage 1, SRAM `0x80000000`) sets up DDR, takes the stream and jumps through `*(0x40000400)`. Who starts DSPI0 as master before stage 1 is open. `[doc]` (stream bytes `[emu]`: payload equals section 7 by SHA-256)
- **Two pins form the handshake:** MAIN's doorbell (GPIO port A bit 4) is the peer's DTIM0 capture event (vector 96); the peer's pin (port 6 bit 2: set via `0xEC09401E`, cleared via `0xEC09402A`) is MAIN's EPORT IRQ4 (vector 68). Peer steps the window state `+8` from 1 to `0xC` (hello "HO"/"HA" at `+0/+2`, `0xA5A5` at `+4`, window RAM test with `0xAAAAAAAA`/`0x55555555`, sample chunks), then installs its frame handler `0x40000934`. MAIN status `0x41bbf448` and state `0x41bb32b0` reach 6. Without a peer, "DSP BOOT FAILURE (TIMEOUT)" follows after `0x12` poll periods (about 1.04 G emulated instructions). `[emu]`
- **MAIN mixes the digital voices and owns the audio clock:** eDMA ch 54 (TCD `0xFC0456C0`) streams a 2 KB ring at SRAM `0x80000000` (64 frames x 8 words) to the SSI TX FIFO `0xFC0C8000`; its **half-way interrupt is the 1500 Hz audio frame** (32 samples at 48 kHz, SSI1 slave; vector 174, handler `0x400a2058`). That handler forces INTC1 source 63 to run the engine tick (vector 191, `0x400a38ce`, 7,550 bytes), which mixes the 8 voices from `0x80003d50` in Q31 and fills the other half. Main L/R sit in ring words 5 and 3 as 24-bit signed (the Q31 mix shifted right by 8). `[doc]`/`[emu]`
- **Frame budget numbers (emulator):** MAIN needs about 117,000 instructions per frame; the peer's frame handler about 86,500 idle and up to 88,900 with a note. digikit runs MAIN at 189.9 M instructions/s (264 MHz core over a measured busy CPI of 1.39); at one instruction per 132 MHz bus tick (88,000 per frame) MAIN did not fit. The peer's hottest code is the voice oscillator `0x4000290e` (98 instructions, 18 call sites, 21-24 % of the frame handler). `[emu]`
- **Profiling clock:** stock MAIN reads DTIM2's counter DTCN2 (`0xFC07800C`, started by the boot loader; MAIN never writes `0xFC078000-0xFC07800F`) and busy-waits on it; DT2/DN2 use DTIM0. `[doc]`
- **MAIN RAM map 1.42:** reset path clears `0x4033a000..0x45566490` (bss end); nothing above. Heap: buddy allocator `0x401036d0` (free `0x401038d6`), descriptor `0x402d5324`, 16 MiB at `0x444e48c0..0x454e48c0` (1.41: `0x444E38C0`). DMA data through the `+0x08000000` alias: slots `0x45570000..0x45609000`, `0x45608000..0x4564f0a0`, eMMC bounce buffers `0x4582f080..0x4583f280`, the sample stage buffer from `0x4584f2c0`, the section-7 transmit buffer `0x4784f2c1..0x478af2cb`. `[doc]`
- **The top 4 MiB of DDR is a ring:** `0x400966e0` memsets 4 MiB at uncached `0x4fc00000` at boot; `0x4009687a` and `0x4009748c` index it as `0x4fc00000 + 8*(i & 0x7ffff)`, advance by `0x20` per frame and hand it to eDMA. So cached **`0x47c00000..0x48000000` is cleared at every boot and written every frame** (that it is the delay memory is open; SyntHack called `0x4FC00000` delay/reverb lines on 1.41). digikit's first `cf.expansion` (`0x47e8b000..0x47fe0000`) sat inside it and was moved. `[doc]` (O35)
- **Why SyntHack's `0x46000000` code got overwritten (inferred):** MAIN builds the 64 sample slots for upload at `0x4584f2c0` (`0x40082334`), and the section-7 buffer starts 32 MB later at `0x4784f2c1`; `0x46000000` and SY FM4's `0x47000000` fall in that stage buffer, and the stock UI's "32 MB" sample limit matches its size. `[?]` (ties to I20, I145)
- **digikit's proposed mod RAM on 1.42 (not canary-tested):** `cf.expansion` `0x478c0000..0x47bf0000` (3.2 MiB, 64 KiB above the section-7 buffer, 64 KiB below the ring), keep area `0x47bf0000..0x47bf1000`, flash cave `0x40339730..0x4033a000` (2,256 zero bytes after the 136-entry init table; 1.41's cave was `0x40338740..0x40339000`). A 31 MiB unreferenced gap `0x458b0000..0x4784f2c1` is deliberately not used. `[doc]` (boot `[emu]`)
- **Board facts same as DT2/DN2:** UART8 `0xEC070000` (same init and TX code), eSDHC `0xFC0CC000` (same driver, same 4-part eMMC whitelist at `0x402d5b40`), DDR 128 MiB at `0x40000000` (bootstrap SDRAM setup byte-identical; CACR `0xa50ce100`, ACR0 `0x4007e020`), soft reset `0x400058f4` (drain UART, `clr.l 0x48000000`, `0x80` to `0xEC090000`). Which eMMC part a real Syntakt carries was open; one unit reports `0x3a4000` sectors (see the digikit-1121 section). `[doc]`
- **Card layout 1.42 (512-byte sectors, MmcFs only, no path filesystem):** header at 0 (magic `0xBEEFBACE`); write-protect bitmaps at `0x800` (272 B, no kit bitmap); 2,048 sound slots of 2 sectors at `0x1000`; 64 sample slots ("SAMP", `0x400` sectors) at `0x2000..0x12000`; two "COKi" arena copies at `0x7a000`/`0x7c000`; working project at `0x7e000`; 128 project slots of 4 MiB at `0x80000..0x180000`. **MmcFs writes refuse sector >= `0x180000`.** An emulated session (save project, save sound, format +Drive) wrote at most sector `0x81f7f` and erased up to `0x17ffff`. `[doc]`/`[emu]`
- **Host-controlled card offsets (stock, all three devices):** the MidiRpc Read/Write/Clear/Copy/Move/Swap handler (`0x4010bd9a`) writes the card through `SafeMmcStreamWriter` at the offset the host sends; nothing bounds it except the card capacity. ## Upgrade receiver, transport state, native bitmaps (OS 1.42, 2026-11-18) {modwerk-1119} {digikit-1119} {synfact-1119}
- **The OS upgrade receiver checks only checksums:** it copies the image into a 2 MB RAM buffer with no size check, so a larger image overruns the buffer, and then erases and programs NOR from `0x80000` for the full claimed length. The 2 MB bound ends 512 KB below the calibration record at `0x300000`, and it is the only guard (rule A76, O34). Traced in the code, not tried. `[doc]` {modwerk-1119}
- **Transport state** anchor on 1.42: `0x4008b838` (digikit; also hook clobber lists). `[doc]` {digikit-1119}
- **Native Bitmap API (1.42 MAIN):** constructor `0x400f72be(object, width, height, pixels, mask)`, clipped rectangle fill `0x400f7fb6`, masked blit `0x400f8f70(dst, src, x, y, flags)`; an eight-word object can borrow pixel and mask arrays with no heap allocation. A 128 x 64 bitmap is 256 big-endian words per array, two words per column; y = 0 is bit 31 of the first word, y = 63 bit 0 of the second; a zero mask bit keeps the destination pixel. This is the bitmap layer; the panel's own row order is a different layer (compare D13). `[emu]` (executed in Unicorn) {synfact-1119}
- **Redraw request:** composition at `0x4000a21a..0x4000a220` passes root + `0x40` to the compose gate `0x4010095c`, which reads the controller's dirty byte at + `0x20`; `0x40100966(controller)` sets it. `[emu]` {synfact-1119}
- **The selected-track model has its own long-label lookup** at `0x40013730` (vtable slot `0x401c3e28`), separate from the base model's; it special-cases the filter labels of parameters 92 and 102. A mod that adds parameters must answer it too, or modals show "Error = value" (Synfact core 2.0.3). `[emu]` {synfact-1119}
- **Unicorn 2.1.4 raises CPU exceptions on unmodified 1.42** in the ARP view's frame and in the modulation probe at `0x40097b3e`; treat such exceptions as emulator limits before you blame a mod. `[emu]` {synfact-1119}

## Synfact findings: AUDIO memory, MAIN CPU profile, project workers (OS 1.42, 2026-11-18/19) {synfact-1120}
- **AUDIO image layout (traced from section 7's code, `tools/study_st_audio_memory.py`):** entry word at `0x40000400` (-> `0x40001070`), code `0x40000404-0x40009f1c` (11,477 instructions reached), tables to `0x40040850`; `0x40040860-0x40041050` is zero in stock (Synfact's AUDIO services sit there); the packed FPGA stream at `0x40041060` unpacks to `0x40042000`. VBR is `0x40000000` (the value is stored at `0x4004005c`); boot points all 256 vectors at an `rte`, then sets vector 96 and the block interrupt. `[doc]`
- **The sample-page receiver has a forbidden page:** MAIN writes a 16-bit page index at window `0x00c` and 2 KiB at `0x800`; AUDIO copies to `0x4004f750 + index * 0x800` with no bound. Index `0x8000` lands on `0x4404f750-0x4404ff50`, AUDIO's own variables and 64-entry sample table: never send it. - **Nothing in the stock AUDIO image names an address above `0x4404f980`** (the end of the zeroed data, named once by the clear; no allocator). That nothing writes the high zone at run time is not yet shown on a unit (Synfact's high-memory probe, type 70, is built for that check). `[doc]`
- **Stock MAIN cost (emulator profile with a calibrated cache model, default project in PLAY, not meter readings):** the block routine `0x400a38ce` is 97.5 % of MAIN's instructions. About 22 KB of code runs every block against an 8 KB, 4-way, 16-byte-line I-cache, so almost every hot line misses once per block: 1 KB less code per block is about 1.5 MAIN points, 1,000 fewer instructions about 0.5. The model (cycles ~ 0.85 x instructions + 40 x misses) was fitted on a unit for AUDIO code and predicted the first Chorus port's jump from 88 % to 100 %. `[emu]`

The MCF5441x can lock I-cache ways 0-1 with `CACR[IHLCK]` (RM 6.4.5); any later write of `0xa40ce100` (the invalidate that mods use after changing code) also drops the lock. `[doc]`

## digikit on a Syntakt unit: section 7 packed, bootstrap stage, key ids, card capacity, write guard (OS 1.42, 2026-11-19/21) {digikit-1121}
First digikit images flashed to a Syntakt (one unit, the maintainer's). Facts marked `[hw]` were seen on that unit; the rest is static reading or the emulator.
- **Two images boot on the unit:** `device-peer` (only the section 7 packer below) and, after the repair below, the full `device` set (runtime, DIGIKIT menu, HEALTH, input, card guard, section 7 packer). The second CPU loads the unpacked section 7, the store works and a content module (digikit/remote) was installed from the workbench, selected, applied and ran with working keys. `[hw]`
- **The patched image did not fit without packing section 7:** Elektron stores section 7 raw (383,760 B, SHA-256 `daf6451c...ec783bc2`); with it raw the patched container was 2,129,312 B, 32,672 B over the 2 MiB upgrade limit (`0x1FFE00`). Packed (aPLib with an 8-byte header: big-endian body length and byte sum) it is 264,194 B. The full set with the guard is 2,079,872 B (16.4 KB free). `[doc]`
- **How MAIN reads section 7 (no stage buffer):** the peer thread (entry `0x40082c04`, made by `0x40082e9c` from the boot thread) loads A2 with the NOR read `0x40116d7a` (6-byte `lea` at `0x40082c24`), reads id 6 into `0x4f8af2c9` and id 7 straight into the transmit buffer at `0x4f84f2c6` (`0xAA` at `0x4f84f2c1`, big-endian length at `0x4f84f2c2`). The only length check is `length + 5 <= 0x60000` at `0x40082d66` (else "DSP BOOT FAILURE (BUF)"); a missing id gives status 1 at `0x40082e84`. No other code reads id 7; the bootstrap and the OS-upgrade receiver do not parse sections. The handshake timeout (about 5.1 s, 19 polls) starts only after both NOR reads and the DMA arm, so unpacking before the stream costs no timeout time. `[doc]`
- **digikit's peer-image hook:** it replaces that `lea` so id 7 is read to the end of the buffer, checked (length, byte sum), unpacked forward with the firmware's own depacker `0x401181ec` (no output bound; returns the length in D0) and checked again (length, SHA-256 of the stock section). On any failure it takes the missing-section path: the second CPU gets no bytes and MAIN shows "OOPS! SOMETHING WENT WRONG, SWITCH OFF/ON TO BOOT AGAIN." The in-place margin of the packed stream is 9,444 B. Boot cost estimate 0.25-0.4 s (not measured on the unit). `[emu]` (proof with a one-byte-changed stream refused) / `[hw]` (boots)
- **The second CPU must get the exact stock bytes:** section 7 carries a second FPGA bitstream (at `0x40041060`) that the peer loads through its own DSPI. MAIN configures the main FPGA itself from section 1: `0x400bd74e` reads id 1, unpacks it with `0x401181ec` to `0x43be315c` (length at `0x43be3158`, 149,516 B), and `0x400bcb4e` shifts it out over DSPI `0xFC03C000` after INIT goes high. This corrects the earlier "the bootstrap configures the FPGA" (section list above). `[doc]`
- **Bootstrap stage and in-place unpack:** the Syntakt bootstrap copies packed MAIN to **`0x40200000`** and unpacks it in place to `0x40000400` (depacker `0x8000041c`; stage constant at `0x800005b2`, `0x800005d2`, `0x80000622`, `0x8000155c`, `0x8000157e`). It checks no bound and no checksum; when the output overtakes the unread stream the decoder runs away and MAIN never starts. Margins at this stage: stock +96,356 B, `device-peer` +67,676 B, the first full `device` image **-42,486 B** (it hung the unit, I183). digikit now refuses a margin under 8 KiB and writes the stream's last tokens as literals to reach it. The emulator had missed it because it installs MAIN directly and never runs the bootstrap's unpack. `[hw]` (hang) / `[doc]` (stage, margins) (I183, compare SyntHack's padded build above)
- **Key ids in key events differ from the Digitakt II/Digitone II:** the id at +`0xc` of a key event is the firmware key index from the decoder table `0x401d7a48`: YES 12, NO 13, RIGHT 17, LEVEL push 48 (a second YES key in lists; the stock compact menu handler `0x400f5c82` treats 12 and `0x30` alike). On DT2/DN2 the same keys are 10, 12, 15 and 49. The flag bits look the same: bit 0 set on a press (cursor keys and RIGHT act on it), bit 4 on a release (YES acts on it). `[doc]` (I181)
- **The card capacity is a driver word:** the eSDHC init (`0x4010ebea`, boot thread) stores the capacity in sectors at `0x444ba720` (from EXT_CSD SEC_COUNT, else the CSD); the 20-byte getter `0x4010f232` returns it, or `0xFFFFFFFF` while the driver is not ready (same hash on DT2 1.17 `0x4012ddd6`, DN2 1.12 `0x4012c49a`, DN2 1.11 `0x4012c1ba`). The part table (7 rows of 32 bytes at `0x402d5adc`) is checked at boot but **not enforced** on the Syntakt: only the self-test reads the result (the DT2 gates its mount on it). Only the self-test makes the pSLC (enhanced area) conversion. `[doc]`
- **One unit's card:** INFO reports `0x3a4000` sectors (1.82 GiB): the `4FTE4R` part with the enhanced area set, the smallest capacity in the table. So do not assume the 32 GB `0x2e1a000` part the emulators model. `[hw]` (I182)
- **What stock touches on the card:** nothing is sized from the capacity. FORMAT +DRIVE erases `0x80000-0x17ffff` and `0x1000-0x1fff` (with SAMPLES also `0x2000-0x11fff`), not the whole card; stock 1.42 touches only sectors below `0x180000`. digikit's Syntakt store is now the fixed area `0x200000-0x300000` (1-1.5 GiB, 512 MiB): 256 MiB above the last stock sector and below the smallest listed capacity. Store writes, listing and removal worked on the unit. `[doc]` / `[hw]` (store)
- **The eMMC write and erase entries:** block write `0x4010f7f8` `(sector, bytes, buf)` and block erase `0x4010f52a` `(sector, count)` are the only MAIN code that writes or erases the user area, except the OS-upgrade finale's raw controller writes of the COKi copies (`0x400bcf7a`) and the CMD6 EXT_CSD writes in `0x4010f3d8` (one-time-programmable card setup: never call it). The write splits requests over 64 KiB by calling itself (return address entry + `0x36`) and is bounded only by the capacity; **the erase checks nothing**, and a count of 0 makes the end sector `sector - 1`. Both start with 8 bytes of `lea; movem.l` (no PC-relative operand); D0, D1, A0, A1 and the flags are dead at both entries; same hash and size on DT2 1.17, DN2 1.12 and 1.11. Five 1.42 callers ignore the result (the console command `0x40080646`, the COKi writer `0x400bcadc`, the Data API Clear `0x400b639a`, the COKi restore `0x400bd608` twice). `[doc]`
- **digikit's card write guard (built for the Syntakt, emulator only):** `before` hooks at both entries refuse a request outside the row of its writer class (stock: `[0, 0x180000)`; the runtime's own write, known by its return address: the store) and return -10, the driver's own out-of-range code, before any lock is taken. The Data API then reports "Failed to write to eMMC". It cannot see the finale's raw writes or CMD6. The guard is on in both Syntakt sets; no refusal was reported from the unit. `[emu]` (SB35)
- **Hook sites found by hash on 1.42 (not checked on this image, `[?]`):** project slot setter `0x4006f2ce`, slot byte `0x40653441`, save exit `0x4001a7d4`, clear-one exit `0x4005a81a`, clear-many exit `0x4005a898`, paste exit `0x400c2116`; USB EP0 setup dispatcher `0x400062e2`, EP0 send `0x4000621c`, setup packet `0x454e4bdc`. `[?]`
- **MidiRpc Ping reply:** on 1.42 the payload is length-prefixed (`1e 16`, 22 request types, `"Syntakt" 00`, 32 bytes); read the name as the first NUL-terminated string after the blob. `[emu]`
- **Recovery path digikit gives:** FUNC at power-on, TRIG 4 (OS UPGRADE), the stock file over 5-pin MIDI DIN; back up the +Drive card first and do not put samples or sounds into the stock slots with Transfer until the Data API guard exists. Whether the logo-hung unit came back through that menu is not stated. `[doc]`
- **Size baseline 2026-11-22:** digikit's `device` set now stores 2,102,528 B against its cap of 2,096,640 B (`0x1FFE00`), 5,888 B over, after the 2026-11-21 set that booted on the unit was 2,079,872 B; growth on the development lane. About 69.8 KB of MAIN's tail is stored as literals because the unpack margin is small; the DIGIKIT menu (19,104 B stored) is to move to the card first. Measured with patchkit; nothing flashed. `[doc]` {digikit-1122}
