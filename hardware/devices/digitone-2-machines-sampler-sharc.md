# Digitone II - machine registration, SHARC mod link, sampler/+Drive layout and field incidents

Sources: elekloader `docs/MACHINES-DN2.md` and `docs/SHARC-DN2.md` (core-dn2 0.2, OS 1.12, "experimental"), dn2mk2's `docs/sampler.md`, `docs/emulator.md`, `docs/user-reports.md`, `docs/CHANGES-FROM-UPSTREAM.md`, `FIRMWARE.md` (OS 1.11). All second-hand, read 2026-10-31. Overview: [`digitone-2.md`](digitone-2.md); internals: [`digitone-2-internals.md`](digitone-2-internals.md).

## SHARC address map of the boot stream (digikit `docs/SHARC-ADDRESS-MAP.md`, from dn2_firmware_explore, DN2 1.11)
- **`load = exec * 2 + 0x28000000`.** Code addresses count 16-bit parcels (VISA), and the entry `0x001c12e2` lands exactly on a loaded region; all 591 of 591 `0x1c`-space jump targets fit. The `0xb8` space (1,025 targets) needs the other mapping (L2 code at `0x20000000`, see the firmware map). `[doc]` {digikit-sharcmap}
- Regions (DN2 1.11, section 7 836,956 B): L2 `0x20000000-0x2001e880` code (125 KB), `0x2001e888-0x2008823c` data; L1 `0x282403f0-0x2826f000` and `0x282c0000-0x282dd52c` rodata, `0x283825c4-0x2839bffc` code (105 KB); DDR `0x80000018-0x8052fbe0` 5.4 MB, almost all fill. About 240 KB of the 837 KB section is code. `[doc]`
- The blob keeps FreeRTOS `__FILE__` strings (`lib\freertos-sharc\tasks.c`, `queue.c`, `port.c` for SHARC_215xx, `heap_4.c`, ...) and the task name "Audio Task", so code can be named from upstream FreeRTOS sources. **These addresses never appear as plain 32-bit words; a word scan finds nothing. You need a SHARC disassembler.** `[doc]`
- An earlier loader parser stopped after 11 KB because of a wrong FILL bit (12 instead of 8). If your parser does not consume the section exactly, check this first. `[doc]`

## A. Adding machines (elekloader machines-dn2, OS 1.12 only)
- Added SHARC **synths** appear in the native FUNC+SYN selector and added **filters** in the FLTR category. Synth menu order: stock synths, then added synths by ID, then MIDI; filters: stock filters, then added filters by ID. `[doc]` {elekloader-machines-dn2}
- Each added synth shows the stock OS a host type of **FM TONE**, each filter a host type of **LOWPASS 4**; the companion sets the host and a mod cannot choose it. A synth inherits FM TONE's track permissions, parameter ownership and MIDI numbers; a filter inherits LOWPASS 4's FLTR page, defaults and parameters. Identity reads, saving and the audio frame keep the custom ID, so the mod's own kernel runs. `[doc]` {elekloader-machines-dn2}
- **IDs:** synth IDs 5-31, filter IDs 6-31, separate namespaces, permanent; the linker rejects conflicts even if a mod omits a resource claim; **there is no global ID allocator**, authors must agree manually. Unused IDs never enter the cached list. `[doc]` {elekloader-machines-dn2}
- **Missing mods:** with the companion installed, a saved synth whose mod is absent keeps its ID, shows as MISSING and is omitted from the selector; its DSP type maps to MIDI (silence) and its CC/NRPN do nothing. Without the companion, stock OS clamps an unknown saved type to FM TONE on load. `[doc]` {elekloader-machines-dn2}
- **Parameter pages:** synth pages add rows after the stock 321 entries. At boot the companion copies the table at `0x401f83a4` to RAM, repoints its 56 references and raises its 54 row bounds by 41 (adds 40 synth knobs plus a filter's G); the sound-load bound accepts IDs through 31. Other addresses: owner map for note-on `0x40288306 + 0x14*v`, value-class accessor `0x400c257c`, CC/NRPN lookups `0x400dc978` / `0x400dca5a`, FLTR knob lookups `0x4006efcc` / `0x4006f004`. **The audio frame is indexed by allocated voice slot, not by track.** `[doc]` {elekloader-machines-dn2}
- Evidence: firmware-free C tests only; the page lists the runtime checks needed (native selector, stock-equivalent audio, both categories, another track, project save/load, the missing-mod control) and reports no results. `[doc]` {elekloader-machines-dn2}
- For Digitakt mk1 the registry of machine IDs is in `digitakt.md` (IDs 4-127; 4 NEIGHBOR, 5 DIGISLICER).

## B. Linking DSP code (elekloader sharc-dn2, OS 1.12)
- One mod can run code on the DSP at the master output; a build contains **either** selectable machines **or** one master-output mod, not both. DSP = ADSP-21569, SHARC+ VISA instructions; silicon stepping not observed. The writer replaces one stock instruction (the profile's single hook) with a call into a bridge; the bridge occupies a fixed range; mod code sits in L2 starting at PC16 `0xbc8000`; mod data uses byte addresses. `[doc]` {elekloader-sharc-dn2}
- **Section 7:** 602,076 bytes stored, 836,956 decoded, **95 boot records** forming two boot images; later loads overwrite earlier ones in order; the writer keeps record order and bytes except for the one hook and bookkeeping for added records. With no SHARC mod, section 7 stays stock. `[doc]` {elekloader-sharc-dn2}
- Regions (half-open, loader byte addresses): bridge and state `[0x282dd600,0x282dda00)`, bridge pitch table and padding `[0x282dda00,0x282dde00)`, **mod (L2) `[0x20090000,0x20098000)`**, replaced stock instruction `[0x2838489a,0x283848a0)`, excluded from new code/data `[0x200fa000,0x20100000)`. The mod's 32 KiB splits 16 KiB code + 16 KiB data in the examples; the last 64 bytes of code are a NOP guard (16,320 bytes of instructions). Stack is separate: bridge declares 116 bytes, a mod may declare up to 428 (544 total). `[doc]` {elekloader-sharc-dn2}
- **Addressing:** L1 loader address = core byte address + `0x28000000`; PC16 addresses count two-byte parcels (the stock hook at PC16 `0x1c244d` is loader byte `0x2838489a`); the stock data pointer `0x268438` maps to loader byte `0x28268438`; the last stock byte loaded into L2 is `0x2008823c`. **An address that exists, or that maps onto another, is not thereby free.** `[doc]` {elekloader-sharc-dn2}
- **Size limits, each checked separately:** section 7 stored `0x100000`, decoded `0xfffff`, update including its 8-byte preamble `0x200000`, flash up to `0x380000` with the container starting at `0x80000`. The section 7 limits come from the stock sender's staging buffers; the update limit is a cautious figure measured over USB, not a proven buffer size. None concern mod RAM or stack. `[doc]` {elekloader-sharc-dn2}
- **Tests in the suite:** SHA-256 of the OS 1.12 SysEx and of section 7 (stored and decoded) pinned in the Python and TypeScript profiles; boot record structure; a no-change write reproduces the stock file; the stock sender's 828 bytes at `0x400cf4b0` hashed against a published analysis; the writer checks packing, the seal, flash bounds and that the main OS unpacks in place safely. `[doc]` {elekloader-sharc-dn2}
- **Evidence ladder in that doc:** static analysis found no direct access, data reference or resolved pointer range touching the mod's 32 KiB (2,979 pointer rows resolved, 192 unknown, of 25,878 indirect accesses - not a complete proof); an emulator canary kept unmodified stock intact over 44 checkpoints and 5,136 DSP blocks and detected a deliberate corruption (cannot see same-value writes, reads, or writes undone before the next checkpoint, nothing about the real cache); C and assembly builds gave identical 99,904-frame captures; on hardware (USB, one unit) sine variants ran, an L2 variant ran ten minutes over notes 36-84 (392 note/release pairs), pattern/page/send/project-load checks were limited. **Not established:** program safety, DAC behaviour, heavy-project stress, real cache and interrupt behaviour, total DSP load, cycle margin. `[hw]` {elekloader-sharc-dn2}

## C. dn2mk2 sampler and +Drive layout (OS 1.11; most numbers are version-specific, v0.13-v0.31)
- Samples travel over USB as SysEx (`dn2samples.py`: hello, send, save, load, forget, lib-send/list/delete/info; Elektron Transfer must be closed). They are written first to a mirror in ColdFire RAM, then fed to the DSP over a TDM "fast link" at about 0.7 MB/s (about 124 words per packet, 1,500 packets/s). Frames are sent first and the directory last so no slot points at missing audio; each 64 KB chunk loaded into the DSP is checked with a VERIFY sum and resent on failure. `[doc]` {dn2mk2-sampler}
- **+Drive regions:** pool image from sector `0x600000` (3 GiB) with a header sector (`DN2P` in v0.15, `DN2Q` in v0.16) holding length and checksum - **the stock storage code does not use anything above 2,224 MiB**; library from sector `0x700000` to the end of the device (~20 GB) with a superblock (`DN2L`), an index of 2,048 64-byte entries and up to 64 folders; each library sample is checked with adler-32 before its index entry is written. `[doc]` {dn2mk2-sampler}
- **DSP RAM pool:** base at DSP address `0x84000000` in the 512 MB DDR; directory magic `SMP1` (count + 128 entries of address, frames, rate, spare) then the frames. A power-on RAM check (`CMD_PROBE`) fills and reads back 256 KB blocks at 143 MB and 256 MB+; if it fails or gets no answer within 4 s the pool stays at 128 MB. Pool sizes by version: 5 MB (v0.14-v0.15), 128 MB (v0.16: 96 MB samples + 32 MB recordings), 400 MB (v0.22+: 0..96 MB and 128..400 MB samples, 32 MB between for recordings, no more than ~5.5 min of recordings). Up to 122 user slots (SAMP 1..122), 124..127 for the recorder. `[doc]` {dn2mk2-sampler}
- Formats: inputs 8/16/24/32-bit PCM or 32-bit float at any rate, mono or stereo; stored as int16 frames in the pool (the doc is inconsistent - an older section says float32); each sample plays at its own rate; recordings 48 kHz int16, peaks between 64 and 32,700 are normalised to 32,700. Slices (max 64): from cue points, `grid:N`, onsets or none; stored with the sample (format word bits 8..15 = count) or, for slices made on the instrument, in a 768-byte area in the last 128 KB of the recordings area (bit 16 marks it). `[doc]` {dn2mk2-sampler}
- Power-on: the RAM check runs first; the pool loads whole in 64 KB chunks; from v0.31 the samples used by the current kit load first and the waveform shows LOADING n%; about 30 s for 20 MB. `[doc]` {dn2mk2-sampler}

## D. dn2mk2 emulator notes (digikit via patched Unicorn)
- Needs Python 3.12, `uv`, WSL; stock Unicorn has a destructive SR read that corrupts condition flags; install `unicorn==2.1.4 capstone==5.0.7` and the patched Unicorn script. After installing a hook in a harness call `uc.ctl_flush_tb()`, otherwise stale translated blocks keep running. CRLF checkouts break shell scripts under WSL. `[doc]` {dn2mk2-emulator}
- Models enough to boot the control processor, render the panel and take input; storage is not served (eSDHC/eMMC identification only, CMD18 returns zeros). Boot ladder snapshots at 60M/120M/200M/280M/400M instructions; on 1.11 only the 400M rung draws frames. DMA timer 3 at 30 Hz and PIT2 are required or the main task blocks forever. Cold boot plays no notes, turns no encoders, loads no project - emulator zeros cannot refute a crash diagnosis. `[doc]` {dn2mk2-emulator}
- 1.11 section sizes: bootstrap 30,302 bytes (dest `0x02010000`), updater 32,768, blob 836,956, section 8 159,948, meta 15; main application task priority 6, entry `0x4002e688` (on 1.10E). Panel: 55 buttons and 10 encoders; code = channel*8 + bit + 1 for buttons, channel + 1 for encoders; channel 6 is non-linear (code 0x00 is shared by (6,2) and (6,3)); the wire carries a whole-channel state mask and the firmware XORs it against the last state to detect edges; 1024-byte framebuffers flushed by `panel_diff`. `[doc]` {dn2mk2-emulator}

## E. Field incidents reported by dn2mk2 users (lessons for any DSP/voice work)
- **DSP time overruns cut all audio** until power cycle. Every voice that does not rest costs time. Dynamic voice allocation spawns voices faster than old ones die away, so eight tracks can need far more than eight voices; locking each track to one voice avoids it. A guard (v0.27) silences voices that do not fit and a CPU indicator shows when it fires. `[hw]` {dn2mk2-reports}
- **A removed table silenced everything:** AMD read a sine table that a later version had removed, so it read uninitialised DSP memory; fixed with a unit test that every table is loaded (v0.30.1/v0.31). `[hw]` {dn2mk2-reports}
- **A guard that wipes with the wrong register** (R0 used as loop counter wrote counts instead of zeros) left voices that went non-finite silent until power-on (v0.33 report; fix planned). Non-finite values (inf/NaN) from engine parameter sweeps (e.g. VO-6 at some CONS/CLEN values) are the likely root; the output guard hides them. `[hw]` {dn2mk2-reports}
- **Voices read their sound by voice number as if it were the track** (Monomachine engines; ~2 of 16 voices sounded). Same family as the skill's "voices are not tracks" rule. `[hw]` {dn2mk2-reports}
- **Stock behaviour users expect to be mirrored:** FUNC+turn jumps values to set positions (NOTE by octaves, LFO DEPTH to -128/0/127.98, SPEED to fixed steps; slices count from C1, not C0). Stock mute only drops a muted track's *new* trigs on the ColdFire, so custom voices get no note but sounding notes end via note-off through the stock AMP. `[hw]` {dn2mk2-reports}
- **After an install** MD and Monomachine tracks went silent until the track was cleared (intermittent, suspected stale voice-slot state or state carried from an older version's project) - always test an old project after an install. A YES on the OS-update prompt could open the app's own pop-up instead of the update question (keys must be routed to stock questions). `[hw]` {dn2mk2-reports}
- **Process:** dn2mk2 forked dnfw at commit `8c40698` (2026-10-01), enforces the safety preflight inside `dnfw mods apply`, tightened its DSP limit to the uploader's actual check, runs `scripts/ship_gate.py` on the exact file of every build, and its `CLAUDE.md` requires the ship gate on every build. Versions v0.4-v0.7 were withdrawn for exceeding the 2 MiB USB limit; v0.17 turned PERC into the Machinedrum (25 machines), v0.18 added the Digitakt II sample engine, v0.19 SLICE. `[doc]` {dn2mk2-changes} {dn2mk2-firmware-md}

## Reading a DSP stop, and what the silicon enforces (dnfw, DN2 1.11) {dn2-dspstop}
- **Which traps are armed:** startup enables only **ILOPI** (illegal opcode, bit 4) and **PARI** (L1 parity, bit 3) besides the RTOS timer and software interrupts. FP-exception interrupts (FIXI, FLTOI, FLTUI, FLTII) are **not enabled**: a NaN in TRUNC/FIX sets only a sticky flag. `[doc]`
- EMUI, PARI and ILOPI record an error code and return address (DN2 1.11 at DM `0x26ef88-0x26ef94`: `0x507` EMUI, `0x502` PARI, `0x501` ILOPI), then jump to `idle; jump .` inside the handler, forever. `[doc]`
- **How to tell a stop from the sound** `[hw]` (inferred from the handler, matching every failed build):
  - **Silence (or a buzz from replayed pages) means a trap.** The core sits in a high-priority handler, so the audio service can no longer run.
  - **A stuck tone (the output DMA replaying its last two pages, ~750 Hz) means a task-level stall,** such as an endless loop, while the audio interrupt still runs.
  - In both cases the ColdFire and UI keep running.
- **ILOPI is what toolchains miss:** an encoding that selas emits and every decoder accepts, but the chip rejects. Examples are negative shift immediates and selas's 48-bit `Rn = <sysreg>` (Type 5a), which put the wrong source code for every register from PC up, so `R0 = EMUCLK` became `R0 = LCNTR`. Use the compressed forms. `[hw]` {dn2-stall}
- **L1 block 2 is not free just because the image leaves it empty:** the PM data cache lives in L1 block 2 (and the I-cache in block 3), sized at boot by `SHL1C_CFG`. Code ending exactly at the last written word lets the sequencer prefetch never-written L1, which can raise a parity trap. Keep written memory after your last instruction. `[hw]` {dn2-dspstop}
- **DSP DDR on the DN2: 512 MB, and `0x80531000-0xa0000000` (~507 MB) is free.** This was measured on the instrument by filling that range with a pattern at boot and scanning it during heavy playback, pattern/kit changes, FX extremes and a save; nothing wrote there. Stock uses the first ~5.2 MB. `[hw]` {dn2-ddr}
- **DN2 stock load from the idle task: ~63-65 % flat, whatever plays.** The frame handler's own count (word 0) is ~416k cycles, and a held voice adds only ~8k: the engine renders every voice every frame. Bursts of +40-49 % of a frame come every 15-30 s (more with note starts), also on stock WaveTone. No frame was missed. `[hw]` {dn2-sharcload}
