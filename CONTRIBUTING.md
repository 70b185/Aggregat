# Contributing to Aggregat

Thank you. Aggregat gets better with every result, correction and source, and most contributions take minutes.

## Five ways to help, from small to large

| Time | What | How |
|---|---|---|
| 5 minutes | **Run a stock test on your unit**: no flashing, just the stock OS and a computer or a phone. | Pick one on the website's [Test your unit](https://70b185.github.io/Aggregat/?t=stock_tests) tab or in [HYPOTHESES.md](hardware/HYPOTHESES.md) section 1, then report with the [Test result form](https://github.com/70b185/Aggregat/issues/new?template=test-result.yml). A result that contradicts the expectation is just as useful. |
| 10 minutes | **Report a bug in Elektron's own OS** that you can reproduce on the stock OS. | [Stock bug form](https://github.com/70b185/Aggregat/issues/new?template=stock-bug.yml) |
| 15 minutes | **Firm up a weak fact**: find the source for an untagged or `[?]` fact and add its evidence tag. | Pick one from [WEAK-EVIDENCE.md](hardware/WEAK-EVIDENCE.md), edit the line in the file it links to, open a pull request. |
| 30 minutes | **Correct or add a project**: your own or one you know. | Edit [data/projects.yml](data/projects.yml) (fields documented at its top), run the checks below, open a pull request. |
| ongoing | **Take part with your project**: keep a results table in your repo. | Copy [research/AGGREGAT_RESEARCH.md](research/AGGREGAT_RESEARCH.md) to your repo's root; see [research/PARTICIPANTS.md](research/PARTICIPANTS.md). |

Issues labelled [`good first test`](https://github.com/70b185/Aggregat/labels/good%20first%20test) are stock tests and
small file tasks picked for newcomers.

## Ground rules

- **Metadata only.** Names, links, status and short notes in your own words. Never firmware, OS files, extracted
  sections, dumps or other projects' code, not even in an issue attachment. Photos, logs and screen text are fine.
- **Every fact has a source and an evidence tag.** `[hw]` seen on a real unit, `[emu]` emulator only, `[doc]`
  stated without a test, `[?]` unclear or inferred. Sources are `{keys}` that resolve in
  [hardware/SOURCES.md](hardware/SOURCES.md) (or a catalogue id). Dates are YYYY-MM-DD.
- **Edit sources, not generated files.** Generated files start with a `generated by` comment: `INDEX.md`, `MODS.md`,
  `DEV-TOOLS.md`, `MUSICIAN-TOOLS.md`, `PROJECT-FAMILIES.md`, `catalog/`, `export/`, `feed.xml`, `llms.txt` and the
  generated pages in `hardware/` (`DUPLICATES.md`, `WEAK-EVIDENCE.md`, `ADDRESS-MAP.md`).
- **Respect other projects.** Read a project's own contribution rules before you open anything there. Aggregat itself
  never opens issues or pull requests in catalogued repos. Do not post firmware-mod links on Elektronauts (Elektron's
  policy since 2026-09-16).
- **Not affiliated with Elektron.** Custom firmware can brick a unit and may affect warranty.

## Before you open a pull request

```sh
pip install pyyaml jsonschema pytest
python3 scripts/validate.py       # schema, device slugs, relations, source keys, incident rules
python3 -m pytest -q tests        # generators and the MCP server
python3 scripts/rebuild.py        # optional: regenerate lists and exports (the scheduled Action does it on master)
```

The [pr-check workflow](.github/workflows/pr-check.yml) runs the same checks on every pull request. A maintainer
reviews and merges by hand, with credit in [research/PARTICIPANTS.md](research/PARTICIPANTS.md).
