# Octatrack (MKI, MKII) - OS 1.40C

Coverage: **first profile** (phase 2). Source: sambanks/octabam docs (`docs/firmware/CHIP.md`, `ARCHITECTURE.md`, `DSP.md`,
`docs/contributing/PLACEMENT.md`, `TRAPS.md`, `docs/guide/BUILDING.md`), read 2026-11-02. octabam marks its facts measured (✅),
inferred (🟡) or retracted (❌); we keep `[hw]` for its hardware rows. Projects: [../../catalog/octatrack.md](../../catalog/octatrack.md).
Key {octabam}. **A different platform from the DT2/DN2:** the ColdFire is an MCF5445x, the DSP is a two-core Freescale DSP56721, not a SHARC.

## Silicon
- CPU: **ColdFire MCF5445x** (board photos read MCF54454VR266 or MCF5445AVR266), 32-bit big-endian. The firmware stores **264 MHz**; internal bus 132 MHz (UARTs, PIT, DSPI), FlexBus 66 MHz, 24 MHz crystal. 128 MB SDRAM at `0x40000000`; NOR flash on CS0, 8 MB decode. `[hw]`
- Audio DSP: **Freescale Symphony DSP56721**, two DSP5636x cores **in one chip**, 200 MHz each, with no external memory.
  - Each core has its own P memory. A **64 K-word shared window** at `$030000` is reachable by both cores; P, X and Y alias there.
  - **Tracks 1-4 run on core 1 and tracks 5-8 on core 0** ("inverted from old assumptions"). Each track's FX1 and FX2 run on its own core. `[hw]`
- Storage: CompactFlash (FAT16/32) through an ATA stack (PIO task-file registers at `0x90000000`).
- The kernel is a **proprietary preemptive microkernel** (banner "ElektronOctatrack DPS-1"), not FreeRTOS.

## Cycle budget (measured with a burn probe on units)
- **4,532 cycles per sample per core** at 44.1 kHz (199.9 MHz measured). The older 4,160 / 183 MHz is retracted.
- About **3,120 cycles/sample are usable for DSP work**; stock takes ~1,410.
- Planning number: ~500 cycles on top of the current reverb with 4 FX1 FILTERs, ~900 with 2. One FX1 FILTER costs 192 cycles/sample. `[hw]`
- Stock FX2 costs per sample (one MKII, 1.40C), dearest first: DJ EQ ~340, LO-FI ~310, SPRING ~300, CHORUS ~295, FILTER ~285, DARK ~255, PLATE ~250, PHASER ~240, EQUALIZER ~190, FLANGER ~145, COMB ~125, COMPRESSOR ~100, SPATIALIZER ~80, DELAY ~0. `[hw]`
- **Words are not cycles:** `move x0,a` 2 cycles, a one-word displaced `move x:(r7+$15),a` ~4, a two-word displaced ~6. Static word counts are a floor; only a burn sweep measures the ceiling. `[hw]`
- **ColdFire access costs** (one unit, 132 MHz, inside the frame interrupt, stock cache settings): register/SRAM/cache hit ~2.9 ns, uncached SDRAM store 36 ns, load 69 ns, cache miss ~80 ns, `cpushl` 46-80 ns. **SRAM is 12-28x cheaper than SDRAM**, and caching a transmit buffer does not help. `[hw]`
- USB costs: one recording buffer is about 6 points of the ColdFire's frame share, USB streaming about 12. Six buffers plus streaming drop frames. `[hw]`

## FX slots
- Every track runs `FX1 -> FX2 -> gain`. FX1 has 3,072 words of Y, FX2 16,384, which is why reverbs and delay are FX2-only.
- **Both menus share one DSP dispatch table indexed by the raw id.** A module on a stock effect's id replaces that effect in both slots, and removing an effect from a menu frees no space. The reclaimable pool is FX1's ten effects, 3,384 words. `[doc]`

## OS format, update and recovery
- Elektron ships the same OS as `.bin` and `.syx` (the MKI and MKII files are byte-identical for 1.40C).
  - `.bin` = ELUP header + seed + XOR-feedback-obfuscated `[len] + ELEK(aPLib(MAIN OS))` + checksum.
  - `.syx` = SysEx-packed ELEK container.
  - The MAIN OS is 1,112,560 B. **No cryptographic signature in any layer.** `[doc]`
- **Validation on update** returns: -1 IO, -2 not a valid OS, -3 length (more than 1 MB + 12 B), -4 checksum, -5 MK1 not allowed (version code below "0156"), **-6 cannot downgrade (below "0178")**. octabam images keep code 0178. `[doc]`
- **The card path:** OS UPGRADE lists `/*.BIN` on the CF, validates, programs NOR from `0x4000` and verifies it word by word. Stock then shows "PLEASE REBOOT!" and never resets the unit itself.
- **Recovery:** hold **FUNC** at power-on, **TRIG 3 = MIDI UPGRADE** (not TRIG 4 as on the small boxes), send the stock `.syx` over DIN MIDI. `TRIG 2` (EMPTY RESET) clears battery-backed RAM and settings, not the card.
  - Pace about 7,460 messages at DIN rate. Filter MIDI clock on that port and merge nothing else into it: a MIDI-hub preset caused a CHECKSUM ERROR.
  - If the unit loses sync, send again slower (60-300 ms between messages).
  - The unit may update its bootstrap after the flash. `[hw]`
- **How stock writes NOR** (1.40C, Modwerk's reading, `[doc]` {modwerk-ot-traps}):
  - OS UPGRADE reads the whole card file into RAM, then erases and programs NOR from there (sector erase `0x40020628`, 256-byte page program `0x400206f4`, the 37 sector starts listed at `0x400a95c0`).
  - The layout is 8 KB boot sectors from `0x4000`, then 64 KB sectors up to `0x1f0000`.
  - Both routines poll the chip themselves and mask interrupts only around the command bytes, so a mod can call them from a task without breaking the frame interrupt.
  - The bootloader below `0x4000` is never written. It depacks NOR from `0x4012` **without checking anything**, so an image that doesn't boot is recoverable over DIN MIDI only. The startup menu's MIDI UPGRADE checks the received file, not NOR. `[hw]` (testers' units)
- **Don't verify a running image against its own RAM:** once running, stock rewrites bytes inside its bootloader copy (`0x400e201e-0x400e2108`) and reuses the RAM after the image. Compare against digests taken before stock started. `[hw]` {modwerk-ot-traps}
- After flashing a build that changes an effect's parameter layout, old projects need their stored values stamped. A select value outside its count stalls the sequencer on first play. `[hw]` ([I28](../INCIDENTS.md#i28-a-select-value-outside-its-count-stalled-the-sequencer))

## Memory and code placement
- **The free ROM is small:** zero runs in `0x400c0000-0x400d8000` total ~8.4 KB, shared by every mod.
  - **The zero region above `0x400d8000` is the PROJECT subsystem's RAM.** A menu table placed in a 15 KB zero run at `0x401087e4` crashed a unit. ([I48](../INCIDENTS.md#i48-a-menu-table-in-a-free-zero-run-crashed-the-unit))
  - Larger code goes to a loader-copied area: octabam's loader is a stub at `0x4010fdf0`, right after the OS image, reached from the boot site. `[hw]`
- DSP code that does not fit a core's P memory (ends `P:0x1fff`) runs from the shared window `P:0x30000-0x3ffff`. This was proven on a unit (PEXT probe, 2026-10-25). `[hw]`
- **DSP scratch:** r7 scratch `$00-$83` is the per-instance block, and **`$84+` hangs the unit**. Stock effects scratch `X:0x20-0xff`, and the hardware dispatcher passes the audio block at X:0. `[hw]` ([I29](../INCIDENTS.md#i29-dsp-scratch-at-84-and-up-hung-the-unit))

## DSP56300 assembler and emulator traps (from octabam's trap register; each cost real work)
- `dsp_asm` **silently mis-encodes**: `tfr a,b` as `rnd b`, and any `mpy` operand order it does not know as `mpysu` (the same trap put garbage on AERIA's headphones, I158). `lua (rN+d),rM` takes d in -64..63 and silently wraps larger values. Labels resolve **by prefix**, so a new label may not have an existing label as its prefix.
- DSP56300 semantics:
  - A logical op on an accumulator leaves the extension byte stale, so the next store saturates to full scale.
  - `move a,b` limits; `tfr a,b` moves all 56 bits.
  - A Tcc pair sharing one compare breaks with any arithmetic in between.
  - `asr #n,a,a` shifts into a0, and Z is set only when all 56 bits are zero.
  - Reading a0 exposes the fractional left shift that a1 hides.
- **No `rep` in an effect's init or proc** (it cannot be interrupted, and the host-command handlers need to run). No dense X work in a DMA's 8K block.
- **Instruction-form rule, as on the SHARC:** a DSP form ships only if a stock payload runs it or a hardware probe approved it. Since 2026-11-15 octabam's gate also accepts a form used by a module proven on a unit (level UNIT). {octabam-1115}
- **Stock Unicorn halves every ColdFire fractional-mode multiply and adds where `msac` subtracts** (the firmware runs EMAC with MACSR = 0x20), and its MAC-with-load decode has three defects. MACSR S/U is bit 6, and in fractional mode it selects 16-bit rounding. These are the same EMAC pitfalls as on the Syntakt and DN2 (rule G-series, `common/toolchain-and-emulators.md`). `[hw]`
- The emulator (`ot_emu`) charges one step per instruction, with no cache or memory timing. A change can be cycle-identical in the port and several percent worse on the unit.

## USB device side (both octabam and Modwerk, measured on units) {octabam-traps} {modwerk-ot-traps}
- **No EP0 reply or OUT data stage may be a whole multiple of 64 bytes.** A reply of 64/128/192/256 bytes left a stale zero-length packet, and the next request returned 0 bytes (once, the unit froze). Stock leaves zero-length termination on in the EP0 OUT queue head, so a 128- or 192-byte OUT stage never completed. Send one byte less, or clear ZLT when priming. `[hw]` Rule A39. ([I5](../INCIDENTS.md#i5-ep0-data-stages-of-a-multiple-of-64-bytes-stall-or-freeze-stock-usb-driver))
- **About one EP0 OUT stage in 50-100 goes unanswered** on a MKII: completed inside the ISR after stock's poll, or stopped part-way. Modwerk runs a 60 Hz tick that finishes a completed stage, or stalls EP0 after 0.5 s so the host resubmits. `[hw]` ([I6](../INCIDENTS.md#i6-about-one-ep0-out-stage-in-50-100-goes-unanswered))
- **DMA reads RAM, not the copyback cache.** A value the CPU stores rarely stayed stale for minutes in USB replies, while values stored every frame looked live. Copy a reply through the uncached alias and send it from there. `[hw]` (Same idea as A28 on the SHARC.) ([I35](../INCIDENTS.md#i35-usb-replies-stayed-stale-for-minutes))
- **A soft reset leaves the USB controller and PHY as they were:** one RAM boot in about six came back with no USB until a power cycle. Stop the controller (USBCMD.RS = 0) and wait ~50 ms before resetting; that gave 20 of 20 good boots. `[hw]` {modwerk-ot-traps} ([I7](../INCIDENTS.md#i7-a-soft-reset-leaves-the-usb-controller-running))
- **Never post key events into stock's queues directly** (two crashes minutes later). Feed the panel parser its own bytes instead. `[hw]` {modwerk-ot-traps} ([I30](../INCIDENTS.md#i30-key-events-posted-into-stocks-queues-crashed-the-unit-minutes-later))

## ColdFire load (Modwerk's meter on a MKII, Oct 2026) {modwerk-ot-traps}
- The Modwerk base with nothing installed shows ~42-47 % CPU. That is mostly stock's own tasks; there is no clean stock baseline yet. `[hw]`
- An FM synth module costs ~8 points just by being installed, plus ~5 while a track plays it. Small effects cost 0.5 points or less on the ColdFire, but their DSP cost lands on their core (BBD on T6: core T5-8 went from ~44 % to 54 %). `[hw]`
- **Uncached module code is expensive:** Analog BD on one track cost ~20 points.
  - 93 % of each call was a write lease whose owner check read the module header through the uncached alias (~0.6 µs a read).
  - With one lease per frame it dropped to ~10 points.
  - Lesson: take locks only where a call writes, at most once a frame, and keep uncached reads out of hot paths. `[hw]`
- UI-task edits can cost milliseconds: a 64-step MIDI rewrite took 3.9 ms per knob turn, mostly stock's lock-index rebuild. Updating only the own track's bits brought it to 0.5 ms. Audio frames stayed ~406-417 µs apart throughout, because it all ran on the UI task. `[hw]`
- **The DSP peak meter shows the busiest single frame** of a 1,024-frame window. A self-test or sync leaves it at ~99.7 % while the mean is flat and the audio fine. Judge overload by the longest frame of a real load, not the peak. `[hw]`
- **Frame budget from the field (Modwerk beta, 2026-11-08):** audio frames are 363 µs apart (16 samples), and the DSPs starve once a gap passes about 515 µs. A unit left stopped and connected for about 23 hours with 6 modules showed 42 % CPU and a longest gap of 423 µs, with no freeze. `[hw]` {modwerk-ot-beta}
- **Settled: the silence after USB DISK MODE was Modwerk's, not stock's** (finding 72, 2026-11-10): stock pauses the DSP while USB DISK MODE is open; Modwerk's base took that pause for a stalled DSP, and its recovery kept the audio stopped until a power cycle. Fixed in the base; on the owner's MKII (1.40C) PROJ > USB DISK MODE, about 10 s, NO, PLAY now plays. Not tested: the walk on a flashed base, a file copy in that mode, an OS upgrade from the card. A mod that watches for DSP stalls must tell stock's own pauses from a stall (rule C12: it was never reproduced on a stock unit). `[hw]` {modwerk-ot-unit-1110}
- **Field stalls with modules (Modwerk beta, 8-10 Nov):** stalls still come within about a minute of installs or restores, before any module code is placed (finding 71), and on a heavy self-test Part (FILTER and DELAY on every track plus FLANGER and PHASER) 1 run in 21 stalled on the live base, 0 in 5 on the lighter Part; only a power cycle recovered. The base's longest fully masked span measured about 14 µs, far under the roughly 200 µs that stops core 0, so masked ColdFire code is unlikely but not ruled out for the stall itself. One field crash record: vector 3 inside a module's ColdFire code. A unit with 6 modules stayed up 70 hours (longest frame gap 424 µs). `[hw]` {modwerk-ot-beta-1110} {modwerk-ot-unit-1110}

## More DSP and boot traps (measured on units) {octabam-traps} {modwerk-ot-traps}
- **An effect's `init` must preserve r1:** the FX1 dispatcher keeps the effect id there and calls `proc` through it. An init that moved r1 jumped to the reset vector and killed the core at project load. octabam's build refuses an init that writes r1/n1/m1. `[hw]`
- **A persistent slot that `init` does not clear holds the previous effect's leftovers.** The emulator boots with zeroed RAM and cannot show it. `[hw]`
- **Resident window code must sit in `0x33da3..0x37eff`:** payload B's boot loop clears `Y:0x37f00..0x3ffff`, and DARK REV writes up to `0x33da2` with default settings (O31). `[emu]` (both cores faulted at boot in the port)
- **A DSP frame counter past `$7fffff` saturates in `move a,nN`**, which stopped a frame engine after 50.7 minutes. Mask counters to 23 bits. `[hw]` ([I32](../INCIDENTS.md#i32-a-dsp-frame-counter-saturated-after-507-minutes))
- **Core 1's load-meter counter** is at `X:$2840` on Modwerk USB bases; module state there gave a jittery pitch. `[hw]` ([I33](../INCIDENTS.md#i33-module-state-on-a-load-meter-counter-gave-a-jittery-pitch))
- **Cold starts:** an early-startup change passed emulator boots and quick power cycles but stalled at the logo after several minutes powered off. Keeping the activation helper resident in the OS image fixed it; the mechanism is unknown. **Qualify startup changes after a long power-off** (rule A40). `[hw]` ([I34](../INCIDENTS.md#i34-a-startup-change-stalled-at-the-logo-after-a-long-power-off))
- **A write-watch on cached addresses is blind to a clear through the uncached alias.** A "free 8.8 MB" region turned out to be the stock delay rings. Before trusting a null result, ask what the instrument cannot see (rule A31). `[emu]`

## From KYOTI (Zac-Kyoti/octatrack-kyoti-fw, OS 1.40C) {kyoti-fw}
- **A core's crash threshold, found on hardware in KYOTI's own cost model:** stock's heaviest effects plus the sidechain compressor model at ~3,516 cycles per sample. The core crashed somewhere between ~3,760 and ~3,830.
  - With DJ EQ in both slots on T5-T8, one extra REPITCH voice (~240) was clean; adding a second (RPS9 ~77 or RPSP ~240) crashed.
  - KYOTI's bar: a feature must not break any configuration that is clean on stock. So **beside stock's heaviest effects a core has room for about one heavy voice**.
  - Note that these "modelled cycles" are KYOTI's estimate, not octabam's measured 4,532 cycles per sample. Compare figures only within one model. `[hw]`
- **The DSP shared window in work RAM is volatile:** at boot, `0x401086f4` is copied to `0x80000000` (`0x3e88` bytes) and the rest is zero-filled up to `0x80004000`. Nothing of yours survives there across a boot. `[doc]`
- **One image for MKI and MKII:** the OS probes `0x46c8d18c` and shows 15 (MKI) or 16 (MKII) PERSONALIZE items. `[doc]`
- KYOTI keeps a merged, confidence-tagged 1.40C address map (`reference/kb/memory-map.md`) that cross-references octabam. It is a good second reading. `[doc]`

## Debugging on the unit by writing a log to the CF card (OctaMax, MKII, OS 1.40C) {octamax}
- When the emulator cannot run the code you need to see (here, the EMAC-heavy frame builder), log from the unit itself.
  - OctaMax added two detours that call the firmware's own file primitives (open `0x40016864`, write `0x400166b8`, close `0x4001677c`, sprintf `0x40013a08`) and write `/HOTDBG.TXT` to the CF card.
  - Pull the card and read it.
  - It works on hardware, and it showed that values seeded in the emulator had been guessed wrong (a voice type byte of 1, not 4). `[hw]`
- **The DSP never plays on its own:** every frame the ColdFire builds a per-voice packet in shared RAM (double buffer at `0x80000000`, selector `0x800000e0`) and pokes the DSP. A voice that stops being fed goes silent without any "stop". `[doc]`
- Recorder buffers live in a paged RAM pool (base `0x40a955e0`, ~89 MB) that survives a project change; the voices are torn down and rebuilt by the load. `[hw]`
- **Restoring state every frame is safe only for CPU-side bookkeeping.** Overwriting data the DSP reads corrupted the audio. `[hw]` ([I31](../INCIDENTS.md#i31-restoring-dsp-read-state-every-frame-corrupted-the-audio))
- An Octatrack emulator built on QEMU (ColdFire MCF54455) plus dsp56300, octemu by markandrus, targets firmware development including USB MIDI and audio; PassOS uses its 20-channel USB audio work. `[doc]`

## Where code and data may go: KYOTI's cave ledger (OS 1.40C, `reference/kb/caves.md`) {kyoti-caves}
Five projects (octabam, octalab, midisc, octemu, ems-octakit, KYOTI) cut code into the same few kilobytes of the same image. Read KYOTI's ledger before you pick an address.
- **The parameter-page descriptor table is live data, zeros included.** It is 31 entries of `0x192` bytes at `0x400d2e52-0x400d5f00`, and a zero entry means "the default". Never place code or data there unless the entry is proven unreachable. `[hw]`
- **The canary test** (from octalab) before anything ships in a new region:
  1. Fill the range with a pattern, or a 32-bit counter so that partial overwrites show.
  2. Use the unit for a full session: load, record, change patterns, save, power-cycle, load again.
  3. Read the range back and compare.

  octamax lost tables to a heap tail and probe counters to a region restored on every load. See rule A43. `[hw]`
- **Scratch RAM `0x80006a40+` is not safe under live audio:** a magic word at `0x80006a60` was overwritten by the next key press on a real MKI while recording; the emulator, which runs no DSP/audio path, kept it forever. `[hw]`
- **Past the image's ceiling, two routes:**
  - append a runtime after the OS image (octabam's loader stub; proven on an MKI);
  - put a position-independent payload with a relocation table on the **CF card** and load it at run time. octemu does this for USB audio (four UAC2 descriptors, iso servicing and a 36 KB ring against ~408 B of slack).

## octabam and octamax findings (2026-11-10)
- **AMP envelope:** the DSP's AMP envelope restarts from zero at every trig START, so with any ATK above 0 a sound that plays across trigs drops out and fades back in, a click on every note. A ColdFire machine holds the DSP at ATK 0 / HOLD INF / REL INF and shapes AMP itself, as SYNTH MACHINE does. Measured laws (Tim Hastie): ATK is a linear ramp of 3.85 ms x 2^(ATK/8.53), at least 16 frames; REL is exponential with tau 0.295 ms x 2^(REL/8.53). `[hw]` {octabam-wavecf} (I58)
- **Crossfader:** stock maps the crossfader through one table of 128 Q15 values at `0x400bcd90`; the panel handler `0x40061e40` and the MIDI CC 48 handler `0x400626ba` rebuild the per-track weights at `0x80003c60` from it. Replacing the table changes scene locks, XVOL and the morph alike; MIDI SCENES mixes linearly on its own. `[hw]` {octabam-xfcurve}
- **Demand loading:** the loader copies a whole effect block (MODULATION, 1,561 words, an estimated ~31k of the 72,512 cycles in a frame) inside one DSP frame hook; the DSP-busy meter reads 99.7 % in that window `[hw]`. The frame interrupt has two waits with no time limit (the loader's wait before each host word, and stock's spin at `0x4000ab26` until the DSP takes the frame's `0x8c` host command); if the DSP stops taking host words, the ColdFire can spin forever `[?]` {octabam-dl} (I57, H22).
- **CF write throughput (STEM REC, MKII):** write time per KB grows with the number of files written at once: 54-92 us/KB for one file, 423 us/KB for eleven (212 after writing whole 32 KB clusters only). Samples streamed by Static machines from the same card slow writes further (252 -> 387 us/KB for ten files); eleven 24-bit files need 2.9 MB/s. `[hw]` {octabam-stemrec}
- **Test host:** octabam's hardware tools run on Linux and on WSL2 with usbipd; MIDI, transport and the load meter work there, but USB-audio capture over usbip delivered only about a quarter of the frames. `[hw]` {octabam-hwtest}
- **Key bus (Modwerk):** the key bus moved from Y `$800-$9FF` to Y `$7E00-$7FFF` on each core, the tail of the first internal FX2 slot, which frees Y `$7F0-$9FF` for a DSP machine's voice. An FX2 effect that fills the whole 16,384-word buffer is then refused on T1/T5; Mini Verb, E-Verb (15,870 words) and BBD still fit. A keyed duck lands within one 5 ms window of the kick, on the same core and across cores; in the DSP simulator the cross-core key arrives exactly two blocks late. Four RINGMOD SC plus four BBD while playing: CPU 85.1 %, core peaks 66/74.5 %. `[hw]` (MKI 2026-10-30, MKII 2026-11-10), memory survey `[emu]` {modwerk-ot-keybus}
- **Module cost (Modwerk survey):** module DSP code runs at 1.4-1.7 cycles per instruction against about 1 for stock, and installed but unused modules add frame-interrupt time (23.3 % -> 28.2 % stopped with 26 installed). `[hw]` {modwerk-ot-options}
- **Internal SRAM has no free holes:** `0x80000000-0x80008000` is the program's `.data`/`.bss`, filled at boot from the image tail; `0x80006964-0x80007574` is the work buffer of the stock audio-analysis task, which writes up to 768 words from `0x80006974`. This explains the KYOTI scratch-word loss at `0x80006a60`. OCTAMAX keeps patch state in DDR at `0x40af0000-0x40af0600`, inside a reserve stock never references, cleared by its boot stub. `[hw]` {octamax-notes} (I59; boot-fill extent disputed, CONFLICTS O23)
- **Sequencer state:** current bank/pattern at `0x800065bd/be`, the cued pair at `0x800065bf/c0` ("nothing cued" when both pairs are equal); cueing the playing pattern cancels in stock, and a switch to the same pattern is a restart with no Part reload. Active bank `0x80000002`, active Part `0x80000003` (disputed, O23); whole-Part apply `0x40009094`. `[hw]` {octamax-notes}
- **Step timing (KYOTI):** the sequencer schedules each step one step ahead, so a Part change sent to the engine in the landing tick sounds a step early; a per-track apply must wait one of the track's steps `[hw]`. The whole-Part apply posts a kernel message and belongs on the UI task; a storage job's done-callback runs on the UI task, which ticks at 1/60 s `[emu]`. Copies with interrupts masked click (I60). {kyoti-reload}
- **Sample pool:** paged in 6 KB pages (MEMORY shows 85.5 MB); KYOTI V1.7 takes 11 pages on DRAM units, octabam reserves 10 MiB when any module runs from DRAM, 18 MiB with STEM REC. `[doc]` {kyoti-build}

## octabam findings (2026-11-11)
- **Audio-interrupt budget (CX OSC on a MKII):** with nothing playing the ColdFire idles at 44.7 % with a mean audio interrupt of 125 us (max 212 us); four CX OSC tracks: 21.8 % idle, 272 us; six: about 12 %, 309 us mean but a 376 us maximum past the 363 us frame; seven: 0 % idle and MAIN clipped. The module now refuses a seventh instance. `[hw]` {octabam-cxosc}
- **Stock icon blit** (`0x400128a8`, a 13-row column word with mask `0xfff80000`): bit 31 is the bottom row and bit 19 the top, so a left shift moves the picture down. Five flashes went into one pixel before this was written down. `[hw]` {octabam-traps}
- **FLEX slices (DRUMMER, OS 1.40C):** in slice mode the voice start `0x4000f450(track, slot, flags)` plays slice `min(STRT >> 1, count - 1)`; the slice table is 64 entries of 12 bytes from +312 of the FLEX slot record `0x100b14f0 + 0x448*slot` (octabam's own STORAGE note said 20 bytes; the code multiplies by 12). `[emu]` {octabam-drummer}
- **Adding and moving trigs:** the sequencer builds each step about 912 samples after the step counter changes, one step ahead; a detour right after the builder (`0x400a2d82`) can add a trig on an empty step or rewrite its micro-timing (one unit is 1/24 of a step). Locks staged for an added trig are ignored, and its lock block holds zeros at boot unless the mod fills it (all 32 lane values of the track went to 0 until DRUMMER wrote `0xff` there). `[emu]` {octabam-drummer} DRUMMER ran on the author's MKII from these sites; two bugs found after the first unit test are I72. `[hw]`
- **Scene locks** sit at Part `+0x662 + (scene*8 + track)*32`, one byte per parameter, `0xff` for none. Retrig time RTIM is exponential: half a step at 79, doubling every 12. `[emu]` {octabam-drummer}

## Modwerk and octabam findings (2026-11-12)

## Frame-interrupt timing and MIDI scenes (octabam, 2026-11-13) {octabam-frameguard}
- **Frame grid:** the DSP raises the frame interrupt once a frame (362.8 µs) and the ColdFire answers with the next frame; the handler's entry is `0x4000aad0`. At START and at a program change one frame interrupt runs 475-585 µs on every image measured, so the next one enters late. `[hw]`
- **Late-entry window:** measured on an MKII, an entry 128-149 µs late is followed by one back-to-back frame interrupt and the unit runs on; 155-223 µs late, one frame is skipped and it runs on; the two stalls logged entered 149 and 155 µs late, after which the DSP took no more frames (sequencer held at step 1, panel and USB alive, power cycle needed). A USB audio capture adds 25-30 µs to the START frame. octabam's FRAME GUARD waits out entries 110-190 µs late until 190 µs; the DSP-side mechanism is inferred (I82, rule A56). `[hw]`
- **Open:** on a test image with 60 µs added to every frame interrupt and a 20-channel capture (the frame interrupt at 91 % of the ColdFire), 7 of 16 STARTs froze the whole unit 8.2 s later, at the pattern's wrap; not seen on shipping images. `[hw]`
- **Scene lock view (stock):** the audio pages draw scene locks from a view byte `0x460d1694` (1 scene A, 2 scene B), set only by the hold-and-turn paths and the scene press handlers `0x40054c80` (A) and `0x40054c5c` (B), which return at once in MIDI mode; the MIDI key's handler (`0x40055548`-`0x40055676`, tail `jmp 0x4007e998` at `0x40055670`) does not set it. So a scene held while switching from the MIDI to the audio tracks shows no locks on stock; octabam's MIDI SCENES hooks the tail to fix that. `[emu]` {octabam-msc}

## TELOS and dspload-ot: boot order, card mount, run-time DSP code (OS 1.40C, 2026-11-14/16) {telos-ot-1117} {elekloader-1117}
- **Boot order on stock 1.40C (instruction counts in octabam's emulator):** the boot site `0x4000050c` calls `0x40001e50`, the DSP bootstrap upload, before the OS (4.27 M); SRAM init `0x40000512` (4.35 M); RTOS handoff with 10 tasks (10.2 M); main's last init call `0x4001fc96` (44.9 M); USB controller init `0x4001e030`, run once (45.3 M); **the card's first mount `0x40061734`** in the sys task (45.8 M); first UI tick that shop mods hook `0x4005595c` (45.9 M); remount (57.6 M); LOAD PROJECT, the engine task's first job (57.6 M); first audio frame (101 M). `[emu]`
- **Files read correctly at the first mount:** a probe opened and read a 16-byte and a 256 KB file with core's file calls there; the engine task had not run a job yet. USB is composed at the controller's init, before the mount, so USB mods cannot be loaded from the card. `[emu]`
- **Code run before the mount:** USB init `0x4001dfbc..0x4001e042` and its descriptors `0x400e2000..0x400e21e0` run or are read once; main's bank-pointer store `0x4001fbd0` once; `0x40025aa2` / `0x40025ac2` (the defaults routine) also in every project load; `0x4009d1de` again later. The OS changes data in its image before the mount, so a loader that needs stock bytes keeps its own copy of `0x400b9000..0x400e2324` from boot (I118, A69). `[emu]`
- **The DSP payloads are gone from RAM by the mount:** A (`0x400e2324`, 79,563 bytes) and B (`0x400f59ef`, 77,061 bytes) are uploaded before the OS starts; by the first mount 76,702 and 73,982 of their bytes read `0xFF`. A payload patch applied later changes nothing. `[emu]`
- **Tasks:** main (TCB `0x46c7ae84`) and ten others with fixed TCBs and stacks (voice, p2a, p2b, p2c, engine, p1b, sys; sys creates storage, keyrepeat and ui); task create `0x400005fc`, current TCB at `0x800068fc`; a TCB keeps its SP at +72. The sys task's own stack holds return addresses into the card-mount path (`0x40061648`). `[doc]` (read from octabam's RTOS model)
- **Other routines:** FAT opendir `0x46c8240e` and readdir `0x46c8244e`; stock YES/NO dialog `0x4006d57c`; the ColdFire soft reset is RCR `0xFC0A0000` = `0x80`. Stock never restarts itself (an OS upgrade asks for a power cycle); whether a unit comes back from that soft reset is not tested. `[doc]` / `[?]` (reset)
- **Sample arena:** 14,602 pages of 6,144 bytes; TELOS's area (2 MB), staging (256 KB) and heap (768 KB) take about 3 MB of it. `[doc]`
- **Run-time DSP code (dspload-ot 0.2, from octabam's demand loader):** code goes in the window gap `P:0x33dab..0x33fff` (597 words for all mods), after four slot pairs at `x:$33da3`. The ColdFire pump sends 100 halfwords a frame, only on frames whose ping word `0x800000e0` is 0, to core 1's `X:0x2901..` and rings `0xa55a` at `X:0x2900`; each block goes three times, 30 quiet frames apart. Core 0 is never written (a transfer there stalls its chain). Core 1's copier sits in SPATIALIZER's words `P:0x868-0x96c`, hooked at payload B's frame head `P:0x76`; core 0 calls bound slots from `ev_dsp_rx`. `[emu]` (not run on a unit)
- **A reverb past its default knobs can write above `0x33da3`:** the gap is above everything stock effects write with default settings only; dspload-ot puts a guard word (`0xc0ffee`) at each end of a block and unbinds the slot when one changes. A write that lands inside a block without touching either guard is not caught. `[doc]` (O31)
- **Compiler and emulator disagree on two ColdFire patterns:** for `move.b (a0)+,(0,a0,a1)` GCC assumes the destination uses the old a0, ot_emu the new one; for a byte push to `-(sp)` GCC assumes SP moves by 1, ot_emu by 2. Which one the CPU takes is not checked; TELOS avoids both (`-fno-ipa-sra`, `dl_memcpy` out of line). `[emu]` (I117)

## Custom LFO design in the Part (Octatrack Manager user guide, 2026-11-16) {octatrack-manager-1117}
- **Each audio and MIDI track's custom LFO shape is 16 steps**, each a value -128..127 and a mode, smooth or stepped (the Part's interpolation mask). A smooth step slopes linearly to the next, and step 16 slopes into step 1. On the device a step is made smooth by holding its trig and pressing TEMPO. `[doc]`
- **Stock Invert maps v to -1 - v** (127 becomes -128, 0 becomes -1) and keeps the modes; **stock Clear** sets every value to 0 and every step to stepped. The tool copies both behaviours; its hardware comparison cases (PE356/PE357) have no published result yet. `[doc]`

## KYOTI V1.8, Clyps and DIRECT JUMP V7.3 (OS 1.40C, 2026-11-13/16) {kyoti-1117} {kyoti-clyps-scope}
Stock data model and sites KYOTI read for its Clyps clip launcher (static reading of 1.40C, used by builds that run on an MKI). MKII untested.
- **Banks in RAM:** all 16 banks are resident. Bank n at `0x400e21e0 + n*0x9b340`, pattern p's slab at `+ p*0x8ed8`: 8 audio track records of `0x91a` B at `t*0x91a`, 8 MIDI records of `0x8b0` B at `0x48d0 + m*0x8b0`. Slab trailer: `+0x8e50` master length (u16, -1 = INF), `+0x8e52` master scale, `+0x8e53/54` pattern length / scale, `+0x8e55` scale mode, `+0x8e56` CHAIN AFTER (< 0 = the project's `0x8000004e`; steps from table `0x400d80dc`), `+0x8e57` Part link, `+0x8e58` tempo. The 4 working Parts (`0x18b2` B each) start at bank `+0x8ed80`, SAVE PART copies at `+0x9504a`, Part-saved flags `+0x9b312`, Part-edited byte `+0x95048`, bank-changed `+0x9b332`. `[doc]`
- **Track record:** self-contained; stock's track paste copies it anywhere. P-locks at `+0x59` (64 x 32 B, `0xff` = none) hold scene-parameter indices and the sample lock is a slot number, so a moved sequence plays through the destination's Part. Trig words `+0x89a`, own length / scale `+0x50/+0x51` (MIDI `+0x28/+0x29`). Byte `+0x899` and the slab tail `+0x8e5c..+0x8ed7` are never written to the bank file (TRAC is 2,329 B on the card): leave them out when you compare RAM with a card copy. `[doc]`
- **Part slice of an audio track** (what stock TRACK COPY carries, 136 B): FX1 / FX2 id `+0x00+t` / `+0x08+t`, levels `+0x12+2t`, machine `+0x22+t`, machine pages `+0x2a+30t` / `+0x1da+30t`, AMP/LFO/FX page 1 `+0x11a+24t`, page 2 block `+0x2f2+30t`, slot record `+0x2ca+5t`, recorder setup `+0x602+12t`. Not carried by stock: scene locks (`+0x662+(s*8+t)*32`, per-scene bytes `+0x1662+10s+t`) and the LFO designer (`+0x1702+16t`, slope `+0x1782+2t`; MIDI `+0x1792+16m` / `+0x1812+2m`). MIDI slice: `+0x3e2+32m` (pages) and `+0x4e2+36m` (channel, bank, program). `[doc]`
- **Applying Part data:** `0x40001f18(bank, part, t)` publishes one track (engine state and memcpy, no kernel call); set the restart bit `0x8000184c` bit t first when the machine changed, as stock's machine edit `0x400973b4` does. The whole-Part apply `0x40009094` (1,492 B, parameters only) snaps in-flight slides on every track. At a pattern switch the engine runs the light apply `0x40009e00`: Part-wide bytes (the engine's bank / Part `0x80001828/29`, scene table, UI block) and, per track, only the LFO setup and only with LFO AUTO CHANGE (`0x80000050`) on; every other new setting reaches a voice at its next trig. `[emu]` (every byte compared)
- **Sequencer tick** `0x400a1eea` (IPL 2): phase D `0x400a1f72`, E builds one step ahead (`0x400a2d7e` audio, `0x400a39c6` MIDI), F `0x400a3ca4`, G master `0x400a3f94`; master step `0x800065b2`, master tick `0x800065b6`; change gate `0x400a42fa`. The wrap body `0x400a43a0` commits a pending pattern whenever one is set and then runs the full switch, whose COND_RESET(-1) call is at `0x400a4850`. A:B pass counters `0x46107918[t]`. `[emu]`
- **Stock switch timing (measured tick by tick):** the new pattern's first step still runs at the outgoing master rate (`SCALE_IX` `0x8000663d` follows a step later); track reload counters stay 0 until the new pattern's first master wrap; MASTER_STEP reads 0 during the last audible step of the master cycle. An A:B pass starts at each track's own wrap (`0x400a536c`) and at the master restart, once when both coincide; FIRST trigs fire only in pass 1. `[emu]`
- **Landing a track in phase:** land one tick before the boundary with the first-fire bit (`0x80006624`) and reload `0x800065d3[t]` = tps - 2, and cancel the old boundary event a full tick ahead. Landing on the boundary tick itself left the old step in place now and then on the unit, because the sample clock and the old event's time are a frame apart there; the emulator's exact clock never showed it (I120, A70). Clocks: audio `0x4610757c` (127,008,000 a second; a tick at 120 BPM is `0x285ff0`, ~21 ms), MIDI `0x46107564` (a tick 16,800). The sequencer runs about a tick ahead of the audio; the engine places events 16 to a frame. `[hw]` (landing) / `[emu]` (values)
- **SILENCE TRACKS** is `0x8000004f` (setter `0x40065a96`, battery copy `0x100b14af`; per-track START SILENT at track record `+3`, -1 = the project's). At a pattern switch the engine hard-kills each silenced voice (`0x40006820`, from the loop at `0x4000d446`) instead of using the declicked note-off `0x40008f84(t)`. On stock a trig on the new pattern's step 0 restarts the voice in the same frame and hides the cut; a DIRECT JUMP landing mid-pattern popped on an MKI until the jump released the silenced tracks with the note-off a tick before the switch (V7.2.2, 2026-11-15, I119). Stock probably pops the same way when a ringing silenced track has no trig on step 0 (H32). `[hw]` (pop, fix) / `[emu]` (mechanism, ot_emu render)
- **Bank files on the card:** chunk lengths are exact (error -51) and a 16-bit checksum covers every byte (-54), so there is no spare byte for mod data; keep it in a sidecar file in the project folder (Clyps' `clypsNN.work/.strd`, 2,568 B per bank, survived SAVE / RELOAD, EXPORT TO SET and DELETE PROJECT on an MKI with hooks at `0x400914de` and `0x4008ed5e`). Direct seek, checked on 816 real files (versions 0x14-0x17): PTRN n at `0x16 + st*n` (st = `0x8eec` from version 0x17, `0x8ee8` before), PART p at `0x16 + 16*st + 0x18bb*p`; OctaLib's table fits 0x17 only. A `.strd` holds 16 PTRN, 4 working PART and 4 SAVE PART chunks. Stock's buffered seek `0x4001660c` keeps a partly read buffer and the parser then finds no tag: seek the filesystem (`0x46c8243e`) to the block and drain the rest. `[doc]` / `[hw]` (sidecar)
- **Battery mirror:** the UI bank's slabs are mirrored at `0x1001614e` (MIDI part `0x1001aa1e`), its Parts at `0x100a4ece`; that is what returns after a power cycle. Stock's `0x4000faf0` writes a whole bank (~620 KB) there; writing only changed records cut a one-track load from 36,568 to 2,466 B. `[emu]`
- **Key layers:** push `0x40031494`, pop `0x4003146c`, head `0x460d165c`; the last layer that lists a key wins (`-1` passes down, `0` swallows), but a key's sub-maps chain across layers (rebuild `0x4003125c`), so stock's FUNC sub-map `0x400bfa1e` still links above yours, and encoder records are copied as they are (no `-1` pass-down). A key held across a rebuild keeps its old handlers (`0x400312e2`). Copy T1's hold delay / repeat (`0x400bfc10`) into every key record you override: a key pressed under one layer and released under another with a different delay leaves its timer in the repeat list `0x460d1660`, and the UI task hangs at its next press. Held flags `0x46c7d8ee + code*24` ([FUNC] `0x2d` at `0x46c7dd26`); TRACK keys select on release; a double tap is a second press while `0x460d5de0` <= 14. Codes: UP `0x33`, DOWN `0x20`, LEFT `0x34`, RIGHT `0x21`, [PAGE] `0x1b`, [CUE] `0x2a`, PLAYBACK..FX2 `0x22..0x26`. `[emu]`
- **Windows:** `0x4005829c(w, h, dx, dy, prio, close_cb)` has five slots; opening priority P closes every window of priority >= P (toasts and SELECT 10, name editor 5, menus 3, project lists 2, Parts menu 1), and close_cb is never cleared. Window `+32` bit 0 is "visible" (the compositor `0x40013ad8` skips it), bit 5 "linked"; the manager finds a free slot by the linked bit, so hide a window by its visible bit, never by unlinking it (I121). Toast font `0x400ba862` (widths `0x400c205c`; a toast line holds 113 px), interface font `0x400ba876` (3x5 glyphs, 4 px advance, widths `0x400c246a`). `[hw]` / `[emu]`

Redirecting fewer than all three gave half tabs and a stray `!` on a unit (I122). Trig LED buffer `0x460ba98c` (trig n = red die 2n, green 2n+1; stock dims to 7), LED layer table `0x460e7628`, push `0x4007e760`, pop `0x4007e81c`. `[hw]`
- **`0x80000012` (MIDI tracks shown) is a long:** a byte read gets its high byte, always 0; on a unit Clyps then showed and loaded audio tracks on the MIDI side, and RELOAD_FROM_PROJECT had the same read (I123). `0x80000000` is the active track of the side shown. `[hw]`
- **Probable stock gap:** TRACK COPY `0x40029754` copies the record and six Part blocks but not the LFO designer, so a pasted track whose LFO uses the designer plays the destination's shape (SB26, not yet seen on a unit). The trigless-trig mask is read at track `+0x08` here, against `+0x10` on this page above (O32). `[doc]`

## octabam stock reading: save path, Parts, key layers, one-shot mask (OS 1.40C, 2026-11-16/18) {octabam-1118} {octabam-pmute-1118}
- **One-shot trig mask:** byte 40 of an audio track record in the bank file (RAM: `bank + pattern*0x8ed8 + 31 + 0x91a*k`, i.e. track record `+0x1f`) is the low byte of the track's one-shot trig mask, bit 0 = step 1 ... bit 7 = step 8. With the step layout of the other masks (byte 7 - s/8) this puts the one-shot mask at `+0x18..0x1f` (inferred). A test project with no one-shots on steps 1-8 reads it as zero, which is how PATTERN MUTE mistook it for spare (I146, O32). `[hw]` (MKI over REMOTE) / `[emu]` {octabam-pmute-1118}
- **Stock mute state:** one per project, bits 8-15 of `0x80000008` for the audio tracks (FUNC+Tn toggles bit 8+n-1). The 22-byte state block at `0x80000000` is mirrored in battery RAM at `0x100b14cc` and restored at boot and by the new-project reset (`0x40025a90`); the power-up sanitiser is `0x4000fe20`. Byte `0x80000011` / `0x100b14dd` is referenced by nothing in the image (octabam uses bit 0 for its layer). A boot with empty battery RAM zeroes `0x100b14dc..df`; a boot with valid RAM writes nothing there. `[emu]` {octabam-pmute-1118}
- **FUNC press:** FUNC's press records sit at `0x400bfc12` (MKI) and `0x400c01f6` (MKII) key tables; its handler gets edge 1 on each press, and stock's double-press filter `0x40040250` (edge 3) does not run for FUNC. - **SAVE PROJECT path:** PROJECT > SAVE is row action `0x40063890`; `0x400255ec` tests whether the project is on the card (if not: SAVE TO NEW `0x40063618`, name keyboard), then a YES/NO popup. Engine job 17 (`0x40085736`) opens the progress window via the sys task (event 43), runs the bank write `0x400919e4` and the project store `0x4008ee74` on the engine task, then `0x40022e80` closes the window with DONE! or stock's error text. 16 banks take over 6 s of emulated card time. `[emu]` {octabam-1118}
- **Engine job 21 is not an engine job:** `{21, fn}` on the engine queue (`0x40085ab6`) posts event 43 to the sys queue `0x460d17ae`, and `0x40062454` runs `fn(1)` on the sys task, which also handles the panel keys; a long file write there freezes every key. Long work needs its own job type at the engine's receive (`0x40084854`). `[emu]` {octabam-1118}
- **First trig at PLAY is built before PLAY:** a gate at the step handler (REC TRIG MUTE's site `0x4009d9a4`) reads the pre-PLAY state for a step-1 trig; gate at the arm `0x40005ff0` instead (a sequencer word with bit 9, `0x4000c9a4`). `[emu]` {octabam-1118}
- **Who holds the keys:** with nothing open the key-layer list holds only the base layer (`0x400c090a` MKI, `0x400c091e` MKII). Pushed layers: MAIN MENU `0x400cbf2c`, YES/NO popup `0x400cdff8`, MIXER `0x400d0384`, TEMPO `0x400bb4ec`, PART window `0x400b9b24` and its menu `0x400ce0c4`, name keyboard `0x400d071c`, progress window `0x400d0bc4`, FUNC sub-map `0x400bfa32`, a page key `0x400bab6e`, a trig held in grid recording `0x400bee74`; SETUP windows SRC `0x400bb7b4`, LFO `0x400bbd22`, AMP `0x400bb960`, FX1 `0x400bc246`, FX2 `0x400bc470`. A toast and a trig held outside grid recording push nothing. A host can read the list to see which window owns the keys. `[emu]` (both models) {octabam-1118}
- **PART window:** cursor `0x460d10c8` is a cross (UP Part 1, RIGHT 2, DOWN 3, LEFT 4); YES selects and closes. FUNC + BANK over it opens a four-row edit menu: RENAME, RELOAD `0x4002dd50`, SAVE `0x4002dd0c`, SAVE ALL `0x4002dcd0` (labels `0x400b9b14`, callbacks `0x400b9b04`). A fresh project has no saved copies (RELOAD shows SAVE PART FIRST!). FUNC + CUE reloads only the current Part, only while it is unsaved; stock has no per-track Part reload. `[emu]` (both models) {octabam-1118}
- **LFO page editor** `0x40038e04(slot, delta)` (LFO from the window list `0x460d1a32`, 3 = designer; A..F = PMTR WAVE MULT TRIG SPD DEP): PMTR/WAVE and MULT/TRIG write marker `0xa0` into the lock cell the slot's SPD/DEP would use; a WAVE above 10 copies the designer table and slope word live. The page-2 editors test no enable bit, so FX1 SETUP knob F on EQUALIZER changes a Part byte no screen shows (SB30). `[emu]` {octabam-1118}
- **Trig removal clears locks, placing does not:** `0x4005fb44` (store `0x400603a8`) clears the step's 32 lock bytes when a trig is removed; placing a trig leaves them (octabam's table had it the other way round). `[emu]` {octabam-1118}
- **Stock WAV writer:** a 44,100-frame 16-bit stereo save is 176,444 B with 176,444 in the RIFF size field, 8 over the specification (SB29, H50). `[emu]` {octabam-1118}
- **DIRECT_JUMP_KYOTI V7.3 hook sites (octabam form, `cd788e9`, 3,938 B in DRAM):** landing `0x400a1f72`, MIDI START gate `0x400a221c`, [PTN] release `0x40043418`, light Part apply `0x40009ebe`, and stock's pattern switch's `jsr` to COND_RESET at `0x400a4850` (tail-jumps COND_RESET, so a COND_RESET detour still sees caller and -1). ## Modwerk findings: stock delay cost, machine prices, card upgrades (OS 1.40C, 2026-11-17/18) {modwerk-1118}

## Modwerk findings: frame guard budget, claim refusals, field records (OS 1.40C, 2026-11-18/19) {modwerk-1120}
- **Frame guard budget (USB bases):** the whole frame interrupt gets 80 % of a 363 µs frame (about 290 µs); stock playback and the other tracks spend that time too, and a track can get two render calls in one frame. When the predicted total passes the share plus saved credit, the guard renders silence for a machine track instead. The guard's skip count and track mask add up since boot, so measure a run by the difference of two reads. A release base logs a `shed` incident at most once every ten minutes (its value: skip count in the low 24 bits, tracks in the high 8), so a short run without a new incident can still have skipped. `[doc]`
- **Headroom differs a lot between units and patterns:** on one MKI (base `9680e9ac`) a tester heard the first skips with a 3 µs render plus about 22 µs of added work in a busy FLEX pattern; on a second MKI with a lighter pattern a 57 µs mean render ran without reported skips. DTCN3 timings include any interruption. `[hw]` (testers)
- **A "module memory" refusal can be a DSP claim meeting a delay buffer:** SC Ringmod 0.2.1 claims Y `$7E00-$7FFF` on both cores (the key bus) and Y `$33DFE-$33FFF` in the shared window. The base checks claims against live and planned delay buffers and counts a module effect's whole 16,384-word FX2 block, so a module effect on FX2 of T1 or T5 (block at Y `$4000`) or T7 (shared window) meets the claims; the refusal said "module memory" (loader refusal 2). In the module pool the set used 161,344 of 786,432 bytes. Seen on a unit on base 0.7.8 (refusals began when Air Chorus sat on T5 FX2); the same may explain I129, whose records do not line up, so that stays unconfirmed. Base 0.7.10 is to give it its own code (12, "meets a buffer") and count reviewed buffer extents for E-Verb, Mini Verb, BBD Delay and Vibrato. `[hw]` (field log) / `[emu]`
- **Emulator trap:** Modwerk's `ot_emu` (2026-10-14 build) never finishes placing DSP code on a 0.7.8 twin, so every package with DSP claims is refused as busy there (`RUNTIME_BUSY`) while the unit keeps the same set. Read such a refusal in the emulator as the emulator's. `[emu]`
- **A stall after a long frame interrupt at low CPU:** one unit on base 0.7.8 (11 modules, CPU 10.9 %, nothing installing) stopped after a frame interrupt of 575 µs, past the about 515 µs at which the DSPs starve, right after FM Synth was added. One record. `[hw]` (field)
- **Stalls while binding:** four units on bases before 0.7.9 stalled with the DSP manager binding a module, two at 95-96 % CPU; core 0's last packet was a BIND and every frame before was on time. Supports the lead on packet work at core 1's frame head. `[hw]` (field)
- **Removing a module with a key layer up is refused** (loader refusal 11, `RUNTIME_UI_OPEN`): Micro Timing could not be removed while TRACK TRIG EDIT's key layer was still up, even after leaving the list for the grid; after a power cycle with the menus closed it went. `[hw]` (MKII)
- **Stock micro-timing writer:** Micro Timing calls stock's per-trig micro timing writer at `0x4002d640` (OS 1.40C); one LEVEL step that rewrites 64 steps costs about 788 of the module's own instructions and 64 bytes of the UI task's stack, plus what stock's writer uses. `[emu]`
- **Two set slots on the card:** the base reads `MODWERK0.SET` and `MODWERK1.SET`; a set imported from the computer is marked so the next boot prefers it, and the other slot stays as the recovery set (also when the computer's clock is behind). `[doc]`
- **Diagnostic log in battery RAM at `0x100fc000`** (size not published; see RAM-TENANCY). `[emu]`

## KYOTI release candidates: spare Part bytes, machine switches, LIVE erase on MIDI (OS 1.40C, 2026-11-19/20) {octatrack-kyoti-fw-1121}
Found while building KYOTI's RC1-RC3 images (VARISPEED VRG3, BLACKPYRAMIDS_303 fixes, the `[BANK]` LED change, ERASE on MIDI tracks). Fixes flashed on the author's MKI; MKII untested.
- **The Part validator zeroes bit 7 of machine slots:** on every load `0x40002318` clamps each machine slot to its descriptor's range; every unused `---` slot has 128 values, so 0..127 stay and anything from 128 up becomes 0. A mod flag kept in bit 7 of such a slot (VARISPEED's remembered QUAN) was lost on every load. The bank read and write copy the page blocks raw, with their checksum. Keep mod values in Part bytes at 0..127 (rule A60). `[emu]`
- **Part bytes the panel never edits or shows:** THRU page-1 slots 2 and 5 (`+0x2a + 30t + 14` / `+ 17`) and the slot record's THRU and NEIGHBOR bytes (`+0x2ca + 5t + 2` / `+ 3`). Encoders on the SRC page, a held trig with an encoder and MIDI CC 16-21 left THRU / NEIGHBOR page-1 `---` slots alone. The slot lookup `0x40031d18` returns 0 for THRU and NEIGHBOR, and their trig handlers (`0x400043f4` / `0x4000463c`) ignore the slot; non-zero values there left THRU's output bit for bit the same. The only stock writer is an SRC page paste of a THRU page (both slots and THRU's slot byte) or a NEIGHBOR page (its slot byte); whole-track copies carry them. - **SETUP-page `---` slots are editable:** THRU page 2 slots 0-5, NEIGHBOR page 2 slots 0-5 and PICKUP page 2 slots 0-3 change from that machine's SRC SETUP page, and also from the SRC SETUP machine chooser with the cursor on that machine's row, on any track. Mod data there can be changed by a user browsing the chooser (the mechanism behind one of the VARISPEED / BLACKPYRAMIDS_303 clashes, I175). `[emu]`
- **Switching FLEX to FLEX re-stages nothing:** the machine commit (`0x4007981c` to `0x400972fc(part, t, old)`) seeds a track's live machine bytes (`0x40001f18`) only on its PICKUP arm (`0x400973da`); otherwise the live bytes follow only at the track's next trig when its stored machine changed, or at a Part apply (PLAY, load, Part change). - **LIVE erase has an audio and a MIDI twin:** `FUN_40041af4` (opcode 8's LIVE branch) calls the audio worker `0x40038874`, or `0x40038668` with the same arguments when `0x80000012` is non-zero. The MIDI per-parameter erase store is at `0x400387b8` (`moveb %d1,%a0@(0x4900)`; audio `0x40038a5c`). Neither clears the trigless-lock flag (`+0x10`) when the step's lock row empties (SB12); the MIDI clear-trigs path clears `+0x00` / `+0x08` and the row but leaves `+0x10` set, which audio clears. GRID REC has no per-parameter erase. ERASE_EMPTY_TRIGLESS_LOCKS now hooks both sites (240 B; MIDI confirmed on an MKI, I173). `[hw]` (fix) / `[emu]` (sites)
- **MIDI step layers:** `+0x00` note, `+0x08` trigless trig, `+0x10` trigless lock, `+0x18` swing (filled on every second step by default), `+0x20` slide. Stock's [FUNC] + trig toggle (MIDI `0x40040f90`, audio `0x40041336`) cycles note, `+0x08`, `+0x10`, `+0x08`. MIDI lock rows sit at pattern `+0x4900 + t*0x8b0 + 32*s` (one byte per parameter, `0xff` none); the trig row painter `0x40034bd4` draws `+0x00` red, `+0x08` green and `+0x10` dim green. The battery mirror of MIDI `+0x10` is at `0x1001aa2e`. This settles the audio side of O32 too: `+0x08` trigless trigs, `+0x10` trigless locks. `[emu]`
- **The `[BANK]` grid asks about every pattern of all 16 banks on each LED refresh** (stock's bank-content test returns to `0x4000fd8c`), and only refreshes while the sequencer runs. Reading only the trigless-lock masks and at most 16 lock rows per pattern cost +0.3-0.5 % ColdFire work on real projects and +2.3 % in the worst case with `[BANK]` held; on an MKI the grid stayed responsive. Stock uses ColdFire `ff1` (ISA_C) at `0x4004098e`, so the OT's CPU has it. `[hw]` (responsive) / `[emu]` (cost)
- **Emulator trap:** a change in the ColdFire's per-frame work alone moves the interleave of DSP passes in ot_emu, so a strict pass-by-pass compare of two images fails while each voice's sequence of values is the same. Compare value sequences, or shift one run by a few frames before blaming the change. `[emu]`

## Modwerk findings: bases 0.7.10-0.7.12, unused-module cost, USB Audio as a module (OS 1.40C, 2026-11-19/21) {modwerk-1121}
- **Key-bus buffer refusal has its own code (base 0.7.10):** a DSP claim that meets a live or planned slot buffer is refused as `RUNTIME_BUFFER` (12), no longer as "module memory" (`RUNTIME_MEMORY`, 2), and the unit's log says which check refused a module at start and how much module memory was in use. A slot's buffer counts as the whole 16,384-word block unless the effect's package has a reviewed extent; E-Verb, Mini Verb, BBD Delay and Vibrato have one and stop short of the key bus, Air Chorus really reaches it. So a key-bus reader (SC Ringmod) is refused only beside a module effect on FX2 of T1, T5 or T7 whose buffer reaches the bus. BBD Delay at its 8,250-word bound: eight FX2 instances on both cores matched their standalone renders with no stray write in `dsp_host`. `[doc]` / `[emu]`
- **What installed, unused modules cost (MKII, 0.7.10 twin, eight FLEX tracks playing):** 24 packages added 6.1 points of frame interrupt (56.6 to 62.7 %) and took the longest frame from 94.9 to 107.2 % of a frame; 5.6 of the 6.1 points came from seven modules with code in the frame (POLY8 2.3: three resting hooks and 11 detours; Repitch 1.4; Slow LFO 0.5; Mute Modes 0.3; Track Solo 0.2; Tuner 0.1), the other 17 (effects, scenes, UI tools, table machines) 0.1 together. None of it is base work that grows with the module count, and none is in the DSP. Stopped readings moved by up to 5.5 points between two empty runs (the delays' tails after a play), so compare playing readings. `[hw]`
- **Per package on a 0.7.11 development twin (each alone, playing, about 51.5 % empty):** at rest FM Synth +2.3, Repitch +2.2, POLY8 +2.2, Euclid +2.2 (+4.3 on a slot), Tape Echo +0.9 (+9.3 on a slot), Slow LFO +0.9, Mute Modes +0.7, every other of the 36 at most +0.2. Kits first read +5.1 because the Part playing changed between the two windows (Kits can select another Part at PLAY); with Part 1 in both it read -0.1. Check which Part plays in both windows before you trust an at-rest delta. `[hw]`
- **Machines and effects rest by themselves (base 0.7.11/0.7.12):** the base rests a machine's module while no track of any Part of the project, working or saved, is that machine (two scans in a row, about 4 s; never during a project load), and an effect module while no slot of the project names its effect id and no live slot runs it; a pick wakes it before it commits and is judged with 3 extra CPU points. A track that names a resting machine without a pick (a paste, a load) renders stock's silent source until the next UI tick. Detours rest only if the package marks them. On a 0.7.11 candidate the published POLY8 alone added 2.2 points and a private build with its 11 detours resting 0.0; the 24-package set read 56.0 % with the published POLY8 and 54.1 % with the resting one (one eight-second window each); a resting POLY8's wake added 2.6-2.7 points. A RENDER_FLEX machine never rests. `[hw]` / `[doc]`
- **UI dispatch with 24 modules (MKII):** 0.7.10's sparse dispatch cut the module runtime per UI tick from 38.6 to 22.2 µs stopped and 110.9 to 52.2 µs playing (empty base 18.6 to 3.6 / 34.8 to 5.4); the frame-interrupt share barely moved. Subscribers are visited in installed slot order, and the first key or encoder handler that takes an event ends the search. `[hw]`
- **Module pool by size:** a whole-set trial of 36 packages (439,244 bytes of package files) was refused whole with `RUNTIME_MEMORY` and changed nothing; the first 24 (308,444 bytes) ran. `[hw]`
- **Stock: PROJECT > CHANGE while playing** asks "PLAYBACK WILL BE STOPPED. CONTINUE?" and stops before it loads, so a project load during playback cannot be reached from the panel. `[hw]`
- **Stock after a RAM boot of a base:** every Part counts as never saved, so RELOAD shows SAVE PART FIRST! (MKII, 2026-11-20). Modwerk's tests SAVE the Part once, while working and saved copies are equal, before they change anything. To restore a scratch Part without RELOAD, copy an identical Part with PART + FUNC + REC and paste with PART + FUNC + STOP, then compare both copies. `[hw]`
- **RAM-boot traps (MKII):** a boot from a twin into itself seconds after its Keep never enumerated on USB (Windows host); the first restoring RAM boot after a power-cycled start took 72 s to answer on USB, later ones 18 s. A twin's Keep writes `/MODWERK1.SET`, the flashed base's set stays in `/MODWERK0.SET`. `[hw]`
- **Fast MIDI soak (MKII, 2026-11-20):** one USB `health` read takes 16-19 ms (median), so a read after every operation caps a soak at about 34 operations a second. A program change while playing lands at the pattern's end; a project with TRANSP RECV or PROG CH RECV off ignores START and program changes without an error; MIDI STOP pauses and the PLAYING flag stays set until a panel STOP. CCs checked one by one against the Part bytes and screen: level 7, mute 49, FX1 A-F 34-39, FX2 A-F 40-45, scenes A/B 55/56, crossfader 48. `[hw]`
- **USB Audio moves out of the base (base 0.7.12, USB Audio 0.3.0-experimental):** until 0.7.11 each of six layouts and USB MIDI alone was a separate base, because the layout set the configuration descriptors, and every base kept a fixed reserve (8 KiB code, 2.5 KiB data, 96 KiB bss). Now a package contributes one USB function (1-4 interfaces on endpoint 3, the only endpoint left; four descriptor blocks in 512-byte slots). When the function changes, the base waits for EP0 to idle, leaves the bus for half a second, rewrites the configurations and comes back; the host then has 20 s to reach the vendor interface before the trial counts as unplugged. The 0.3.0 package holds 10,288 B of image and 94,152 B of bss from the 768 KiB module pool. `[hw]` / `[doc]`
- **USB stock sites the base raises hooks from:** the USB interrupt's transfer path (shim at `0x4001e606`), bus reset and session end (`0x4001e91c`, `0x4001e952`), stock's unknown-request tail before it stalls (`0x4001de64`, SETUP packet at `0x46c8ce08`), and the audio producer in the frame interrupt, every 16-sample block, at `0x4000d9a0` before stock clears `0x46104d4e`. SET_INTERFACE `0x4001dd04`, GET_INTERFACE `0x4001d824` and the EP0 page `0x4001d4b2` are still patched by the function itself. `[doc]`

All six layouts recorded on macOS; Windows, Linux, full-speed hosts and a physical Outbox 8 are untested. `[hw]` (macOS) / `[emu]`
