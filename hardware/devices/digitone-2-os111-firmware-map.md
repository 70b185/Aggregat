| Parameter table | `0x401f7fc8`, 320 records x 60 B (word +0 handler, +0x08 group, +0x0C id, range fields after). dnfw's memory map gives `0x401f7fc4` - the 4-byte difference is unexplained; on 1.12 dn2-cfw counts 321 rows at `0x401f83a4` `[?]` |

| Kit / voice setup | root = `0x4018a97a()`, kit = root + 0xF4; kit for VOICE SETUP `0x4003e41a(root)`; active track `0x40046bfe(root + 48)`; voice settings kit + 17092 / 0x5CE0 + 2t, setter `0x40031620`; VELOCITY TO VOL `0x4004b304`/`0x4004b334` |

| Patterns | save `0x400de75e`, load `0x400dccc0` + `0x400de5e6` (ids < 128); edit context of the active track `0x4003efde(root)` = P + 70 + 132t; place a trig like the grid: `0x40054690(ctx, step, 1, 1)`; NOTE/VEL/LEN are 6-byte records via `0x400350b6` (0xff = not locked); LEN table `0x402a0f48` |

| Machines | MACHINE menu = FUNC + SYN; list `{0,2,1,3,4}` at `0x401ddd58`; descriptor dispatch `0x400c248e` (type <= 4, RAM table `0x42432b24 + 44t`); per-type accessors bounded `type <= 4` cluster at `0x400dc144..0x400dc376`; machine setter `0x4004cc08` |
| Audio ISR order | ISR `0x40025e36` (one per DSP block): TX hook site `0x40025e82` -> driver sends the frame built in the **previous** ISR -> notes/locks `0x40026xxx` -> mirror smoother `0x4002717e` (EMAC one-pole `0x400db160` into mirror `0x800068e4`) -> LFO tick `0x400272d4` (evaluator `0x40137a8e`, bound `0x40137a9e`, mirror `0x80006906 + 202*voice`) -> frame build; the ISR tail forces INTC0 source 44 (vector 108 = sequencer tick `0x400d7864`), which forces 57 (vector 121 = step processing) |

## SHARC (DSP, section 7) map
| Area | Facts (OS 1.11 DSP; identical in 1.12) |
|---|---|
| Addressing | addresses are short words (sw). Load byte address: L2 = 2 x sw + 0x28000000; L1 = 0x20000000 + 2 x (sw - 0xB80000); DDR code sw 0x800000.. = 0x80A00000..; data `0x002xxxxx` in code = loader `0x282xxxxx` |
| Audio task | `0x1c9fe7` -> `0x1c9d6b` (reads EMUCLK before/after: the DSP measures its own load -> reply word 0) -> command 3 -> render `0x1c2712` |
| Render chain `[hw]` | copy the 672-word frame to `0x25c48c` (at `0x1c302d`, just before the voice render; converters before it read the PREVIOUS block's copy) -> voice render `0x1c8ef1` -> FX-bus mixer `0x1c1738` -> main mix `0x1c1f1e` -> outputs `0x1c244d` -> soft clipper `0x1c30cd` (+/-0.693); main out floats at `0x268438` (L 0..31, R 32..63) |
| Link frames `[hw]` | in = `0x2c29d0 + (bank << 12)`, reply = `0x2c49d0 + (bank << 12)`, bank = DM(`0x2c0450`); the SPI receive DMA ping-pongs between the two in-banks; its completion callback `0x1ca04a` (registered at `0x1cb7dc`) toggles the bank |
| Hook sites used | `0x1c1fef` (`R2 = DM(0x257980)`): main mix, all 16 stereo track buses complete - per-track effects; `0x1c3054`: the FX-bus mixer's CJUMP `0x1c1738` - post-voice, per-voice stereo buffers ready (**the mixer takes R4 and R8 - preserve them**); `0x1c9543`: voice chain after the pre-filter stages, before the filter dispatch - per voice, mono, pre-filter; `0x1c90a6`: engine dispatch (table `0x8052db90`, M4 = engine index) - a new machine type needs a hook here |
| Voice chain | each stage loops over the 16 voices' mono buffers (DDR `0x804acf90 + 128v`, pointer table `0x254a60`): engine render -> BR `0xb8251b` -> OD pre `0x1cdb56` -> DC filter `0xb80c39` -> SRR pre `0xb8265b` -> base-width filter pre (`0xb81368`) -> [`0x1c9543`] -> filter dispatch (table `0x8052dbc0`, `JUMP (M13,I12)` at `0x1c9595`; filter switch `0x1c9580` reads `0x254ad4 + 4v`, >= 7 = no filter) -> OD/SRR post -> base-width post -> amp -> pan `0x1c9ae7` -> stereo voice buffers `0x257ee8 + 256v` (L 0..31, R 32..63; about +/-0.07 full scale; main mix x 14.1254) |
| Engines `[hw]` | the dispatch at `0x1c90a6` is a per-voice prep step; the renders are separate 16-voice loops at `0x1c93e5..0x1c9447`, each testing the voice's engine word = param block `0x2554b8 + 564v + 436` (rewritten every block by `0x1c2997`): FM TONE `0x1c54c7`, WAVETONE `0x1c6d4a`, FM DRUM `0x1c778b`; 4 (MIDI) matches no loop - **a new machine must set the engine word to 4 or it also pays for a stock render**; engine state `0x2495e0 + v*0x55c` |
| Voices / buses | voice -> track map int16 `0x257898 + 2v`; per-voice mute bytes `0x2578c8 + v`; send gains (chorus `0x257a24 + 4v`, squared, mute-gated) into delay bus `0x25af68`, reverb `0x25b268`, chorus `0x25b568`, taken from the voice buffers; the main mix zeroes 16 stereo track buses `0x258f68 + 256t` (L 32 words, R at +128 B), sums every voice into its track's bus x 14.1254 (a stolen voice fades over 31 samples via byte `0x2578b8 + v`); per-track mono sums `0x259f68 + 256t` after the FX mixer |
| Note-on in the DSP | in the frame copy `0x25c48c`, word `0x25c4ac` bits 16 + v = note-on of voice v this block, `0x25c4b0` = off mask; engines restart at a note-on (the pre-amp signal steps; the amp hides it - a resonant PRE effect will not) |
| External input | per block `0x1c9d00` converts the codec receive ring (`0x2c0678 + 256 x (DM(0x268a38) & 1)`, L/R interleaved Q31) to floats L `0x268538`, R `0x2685b8`; after IN level/BAL/pan the FX-bus mixer writes IN_BUF `0x25bc68` (4 lines x 32); the main mix adds it x 14.1254 |
| FX | chorus `0xb84d5c`, delay `0xb8482c` (2 x 2^19-float rings, state `0x8005912c`), reverb `0xb836bc`; chorus params `0x257950` (dry/wet forced 1.0: send FX returns are wet only); converter about `0x1c2d80..0x1c2fc5` |
| Frame -> sound record | in the 2688-byte frame, voice v's sound record (+0xda + 146v) maps slot s to +2(s-25) for s <= 65, 82+2(s-66) for s <= 79, 110+2(s-80) for s <= 92, 136+2(s-95) otherwise; values are raw (knob << 8 OR fine), the DSP divides by 32768 (or 32512); voice level is about squared; velocity curve 0..4 |

## Boot stream (section 7) format, as the skill's `dspblocks.py` handles it
ADI boot stream: 16-byte block headers (code `AD xx xx 01`, target, count, argument; the 16 bytes XOR to 0 via HDRCHK in byte 2) plus payloads, ending in a FINAL block whose target is the entry point. Free and hardware-proven: L2 code `0x20090000` (sw `0xBC8000`) .. `0x20098000`, L2 data `0x20098000` .. `0x200A0000` (zero-filled at boot by a FILL block), more up to `0x200B0000`. **Why 8n+4-byte blocks silence the unit:** the ADSP-21569's L2 keeps ECC per 64-bit word; a boot DMA ending in half a word leaves a bad ECC and the I-cache fill over the block's end faults the core on the first block - the emulator copies bytes without ECC and plays them. `bootblocks.py` fails any added block (L2 `0x20088400..`, DDR code `0x80a00000..`, DDR data `0x84000000..`) that is not whole 32-byte lines. `[hw]` {dn2-skill-scripts}

## The static checks, exactly (from `hwrules.py`, `encodecheck.py`, `shapecheck.py`)
- **LOOP-ISA**: last 11 instructions of a hardware loop (all of a short loop) must be legacy 48-bit ISA - stock 1.11 obeys it in all 286 loops. **LOOP-END**: nested loops must not share an end address. **LOOP-LCE**: no `IF NOT LCE` in the last 11 instructions of a counter loop. **LOOP-CALL**: no CALL in the last 5 instructions of a loop. **BRANCH-12**: at least 12 valid 48-bit instructions' worth of code after every branch. **BRANCH-WIN**: no two branches in one 48-bit (3 short-word) window. **DAG-SAME**: no same-DAG DAG-register store and no post-modify same-DAG DAG-register load ("the root cause of silent units"; stock real code has zero of either). PRM references 4-14, 4-41, 4-42, 4-44. The checker reports only violations not present in a stock baseline. `[hw]`
- **Encoding census**: for every instruction you add, its shape (registers and constants blanked) is looked up in stock real code; bits that are constant in every stock instance must match - catches encodings a decoder accepts but stock never emits (the negative-shift sign-bit case). **Shape census**: lists instruction shapes stock never uses - not an error, but each must be justified from the PRM. The skill's assembler decodes every emitted instruction and compares it with the intended text, and its 48-bit packer schedules loop bodies so they stay hwrules-safe. `[doc]` {dn2-skill-scripts}

## Talking to the running unit over USB (MIDI RPC, as used by Transfer/Elektroid and the skill)
- Framing: `F0 00 20 3C 10 00 <8-in-7 encoded body> F7`; body = sequence (2 bytes, big-endian), `00 00`, opcode, payload; the reply opcode = request OR 0x80. Opcodes seen: `0x01` ping (device name and opcode list), `0x04` screenshot, `0x50` OsUpgradeStart (u32 size big-endian, "sysex", auto-commit byte), `0x51` OsUpgradeWrite (2 KB blocks with CRC32), `0x52` OsUpgradeEnd (1 commit / 0 cancel). OS 1.11's RPC handlers read every u32 big-endian. Upstream documentation: dnfw `docs/midi-rpc.md` (derived from Elektroid). `[doc]` {dn2-skill-scripts}
- **Upload pitfall `[hw]`:** with auto-commit the OS posts "upload complete" to the upgrade view as the last block is parsed; on the first upload after a boot that view is not open yet, the event is lost and the unit sits on "OS UPGRADE / Receiving". The skill therefore sends Start **without** auto-commit, all blocks, waits a few seconds, then End(1) - the End handler checks every byte arrived and posts the event itself; the stock OS then validates the container and asks UPGRADE OS NOW? (press YES). Keep USB silent while it writes flash (~90 s), then ping until it answers; one upload, no retries. Raw OS SysEx sent over USB to the running OS is ignored. Python + mido can hang at exit in CoreMIDI. `[hw]` {dn2-skill-scripts} {dn2-skill-setup}
- This explains the "stall on Receiving/PREPARING" reports in Overtone 1.0 and elsewhere ([`../common/recovery.md`](../common/recovery.md)).

## Build pipeline (`cfmod.py`, `dspblocks.py`, `zcache.py`)
- C/asm is compiled with m68k GCC `-mcpu=5475 -Os` (no libc) and linked at `0x46800000` (free on 1.11) by `dnfw.patch.cbuild`; dnfw's 138-byte startup loader copies the appended `DNFW` area there at boot and calls your init; **every hook site is checked against the stock bytes before it is overwritten - a wrong address fails the build**; `context()` asserts bytes a hook relies on without writing them; section 3 is recompressed and the container re-signed. API shape: `jsr(addr, stub, stock=...)` (6 bytes), `jmp(addr, stub, displaced=N)` (the stub replays the displaced bytes), `patch(addr, old, new, why)`. `[hw]`
- Flash space is the binding limit (2 MiB upgrade buffer): dnfw's packer is greedy with a one-step lazy look-ahead over a 32-deep match chain; a 192-deep chain packs MAIN OS 0.8 % and section 7 0.5 % smaller within the same format and window (depth 1024 packs worse); pure-Python aPLib costs ~20-50 s per section in CPython, ~3 s in PyPy; a content-keyed cache skips unchanged sections. `[hw]` {dn2-skill-scripts}
- Examples: `double_time` hooks `move.l 0x402a0dec,%d0` (6 bytes) at `0x40027ac0` with `jsr dt_stub`, keeps the live d1/a0/a1 via `lea -12(%sp),%sp; movem.l ...,(%sp)`, and caps the doubled step under one 96 ppqn subtick per block (112,000 units); `track_trim` adds an L2 code block, a CALL hook and an fxdsl kernel (-6 dB on track 1, A/B ratio 0.5000).
