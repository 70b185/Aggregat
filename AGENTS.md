# AGENTS.md

Instructions for coding agents (Claude Code, Codex, Cursor, Copilot and others). Two kinds of agent read this file:
**users** of Aggregat, who develop a mod or tool for an Elektron device and want the knowledge here, and
**maintainers**, who change this repository. Read the section that fits.

## If you are developing for an Elektron device

Aggregat is a second-hand knowledge base: facts, rules and failures collected from public projects. It contains no
firmware and no code from those projects. Custom firmware can brick a unit.

1. **Load the context pack for the device first**: [`export/context/<device>-brief.md`](export/context/README.md)
   (safety rules, recovery, stock bugs, incidents, open questions, catalogued projects; 2k-11k tokens). Load the full
   pack `export/context/<device>.md` when you need the hardware facts too. Device slugs are in
   [`data/devices.yml`](data/devices.yml).
2. **Follow the safety rules (A1-A49) in [`hardware/AGENT-RULES.md`](hardware/AGENT-RULES.md) without exception.**
   Above all: never touch the bootstrap or updater section (A1), know and write down the recovery path before
   anything is flashed (A2), verify every image before it is written (A6), gate what you ship (A8), and say "not
   hardware-tested" wherever it is true (A18).
3. **Before you blame your own code**, check [`hardware/STOCK-BUGS.md`](hardware/STOCK-BUGS.md) (bugs in Elektron's
   own OS) and [`hardware/INCIDENTS.md`](hardware/INCIDENTS.md) (what went wrong on real units, and why).
4. **Check what others built** before you build it again: [`research/FEATURE-OVERLAP.md`](research/FEATURE-OVERLAP.md) and
   [`catalog/`](catalog/README.md). Before you place code or data in RAM, check who else uses that range:
   [`hardware/RAM-TENANCY.md`](hardware/RAM-TENANCY.md) and [`hardware/ADDRESS-MAP.md`](hardware/ADDRESS-MAP.md).
5. **Query instead of reading** when you need something specific:
   - the MCP server in [`mcp/`](mcp/README.md) (`search_facts`, `rules_for`, `check_address`, `preflight`, ...), or
   - SQLite directly: `sqlite3 export/aggregat.sqlite` (tables and example queries in
     [`export/README.md`](export/README.md)).

**Evidence tags.** `[hw]` seen on a real unit, `[emu]` emulator only, `[doc]` stated without a test result, `[?]`
unclear or inferred. Prefer `[hw]`. Treat everything as second-hand: re-check addresses and byte patterns against the
cited source (`{key}` resolves in [`hardware/SOURCES.md`](hardware/SOURCES.md)).

**Cite facts by their stable id** (`digitone-2#3f9a01bc`, column `fid`), not by line number; ids survive edits
elsewhere in the file.

**Moving to another OS version?** `scripts/anchor_translate.py OLD.bin NEW.bin --base 0x40000400 <addresses>`
translates addresses between two images you supply, by byte-pattern anchors, and says how sure it is per address
(goal G5). Never commit the images.

**Before you release**, run the [mod-author checklist](docs/MOD-AUTHOR-CHECKLIST.md) and paste its status block into
your README.

**Give back.** Copy [`research/AGGREGAT_RESEARCH.md`](research/AGGREGAT_RESEARCH.md) into your project's root and keep
its results table, or report a result with the
[test-result form](https://github.com/70b185/Aggregat/issues/new?template=test-result.yml). A failure on a real unit
is as valuable as a success.

**Ground rules that apply to your output too.** Do not commit or link firmware images, extracted sections or other
projects' code into this repository. Do not post firmware-mod links on Elektronauts (Elektron's policy since
2026-09-16).

## If you are changing this repository

- **Edit sources, never generated files.** Sources: `data/*.yml`, `hardware/**/*.md` (except the generated ones
  below), `research/` (the research map, feature overlap and participants; `research/AGGREGAT_RESEARCH.md` is
  generated). Generated (they carry a `generated by` marker): everything in `catalog/` (the project lists),
  `hardware/DUPLICATES.md`, `hardware/WEAK-EVIDENCE.md`, `hardware/ADDRESS-MAP.md`, everything in `export/`,
  `feed.xml`.
- **Rebuild everything** after an edit: `python3 scripts/rebuild.py` (runs the generators in the right order).
- **Check before you commit**: `python3 scripts/validate.py` (schema and cross-references) and
  `python3 -m pytest -q tests`. Pull requests run both.
- **Metadata only**: names, links, status and short notes in our own words. Every entry needs a source and a date.
- **Evidence**: every new fact gets an evidence tag and a `{source-key}`; add the key to `hardware/SOURCES.md`.
- **Update procedure** (finding and folding changes from catalogued repos): [`docs/UPDATING.md`](docs/UPDATING.md).
- **Style**: plain English, short sentences, facts before opinions, dates as YYYY-MM-DD.
