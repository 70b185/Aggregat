| # | Goal | Where it stood | What would move it |
|---|---|---|---|
| G1 | **Every device has a recovery path somebody has actually used** | ✅ DN2, DT mk1, Octatrack, A4/Rytm MK1; 🟢 DT2 (one report, OS 1.16); documented for Syntakt (SyntHack) and Heat +FX (official). 🟢 Digitone mk1 (one report, OS 1.44). Every phase-1 device now has a used or official recovery path. | T1; test H16 |
| G2 | **An honest load/headroom measure per device** (rules A25, A34, A37) | ✅ DT2 (idle-task measure on a unit), DN2 (elekloader busy meter, with the "busy is not headroom" caveat). ❓ Syntakt (two readings conflict, O3). ⬜ Heat +FX, Digitone mk1 voice CPU. | T4, T9, T10; tests H15, H17 |
| G3 | **Shared-silicon knowledge transfers between devices** | At least six phase-1 boxes use MCF5441x-family ColdFires (DT, DN, DT2, DN2, Syntakt, Heat +FX); DT2 and DN2 share the SHARC and 85 % of its functions. Many rules were found on one box and are only assumed for the others (e.g. A39 USB, A28 cache write-back). | T3, T12, T19; tests H7, H12-H15, H17 |
| G4 | **Emulators you can trust for more than "it boots"** | ✅ known gaps: no memory stalls (device cycles ~2x emulator), no pipeline model, EMAC fractional-mode bugs in stock Unicorn. ❓ digikit: real-time DSP audio. | T14 |
| G5 | **Mods that survive OS updates** | Every mod pins one OS version; address translation between versions is done ad hoc. Good news for DSP work: the SHARC sections are **byte-identical** between DT2 1.16 and 1.17 and between DN2 1.11 and 1.12 (digikit finding 53), so only the ColdFire side moves. | T6, T8 |
| G6 | **Official numbers instead of guesses** (MIDI CC/NRPN tables, startup menus) | The manuals' appendices were beyond what our fetcher extracts. | T13; test H4 |
| G7 | **Talk to every unit the same way** (SysEx dumps, the RPC, device ids, project files) | The dump frame, 7-bit packing and checksum are the same from the Rytm (2014) to the DN2; the type bytes differ; three id namespaces mapped (T22). Project files are zips with LZ4 content. Per-device gaps: Heat +FX RPC, DT2 project format. | T18, T22; tests H1, H2, H3, H18 |
| G8 | **Mods that coexist** (with each other, with Overbridge, with stock projects) | DT2 and DN2 RAM and hook use of five to six platforms compared: several start at the same addresses, the DT2 flash cave has five users (T21, T23). Open: O18, O19 (O17 settled as S17). | T16, T23, T24; tests H5, H6, H8-H11 |

## Hypotheses (inferred, not yet shown on a unit)

| # | Goal | Inference | Unit | Test |
|---|---|---|---|---|
| H1 | G7 | Each unit has three different ids: SysEx device byte, product id, Overbridge USB id. Expected: DT2 `0x14` / `0x2A` / USB `0x0B2B`; DT1 `0x0A` / `0x0C` / `0x0B2C`; DN2 `0x15` / `0x2B` / `0x0B34`; Heat +FX `0x13` / `0x20` / `0x0B53`. The USB id's low byte changes with the USB mode (`0x012B` MIDI, `0x102B` audio/MIDI on the DT2). | all four | Read the USB ids in each USB mode (`lsusb` on Linux, System Information on a Mac, Device Manager on Windows). Read the product id with Elektroid's device info. |
| H2 | G7 | Unsaved edits survive a power cycle on the DT2 and the DT1 as on the DN2, because the stock edit writer stores each edit in the sound record at once. | DT2, DT1 | On a throwaway project, turn a filter knob, do not save, power-cycle. Is the value still there? Also try a parameter lock. |
| H3 | G7 | A received pattern dump lands in the slot armed on the unit, not in the slot its index byte names (shown on the DN2 by syxgrid). | DT2, DT1 | On a throwaway project, send a pattern dump with index A05 while A02 is armed, using Elektroid or digi-roll. Where does it land? |
| H4 | G6 | The DT1 recorder holds at most 33.0 s (1,584,000 frames at 48 kHz, mono). | DT1 | Record with free length until it stops; time it. |
| H5 | G8 | Overbridge rejects a modified OS whose container version field differs from stock (shown on the DN2, Digiwerk OB01). | DT2, Heat +FX | No new flash needed if you already have builds: does Overbridge connect to a build whose version field was changed, and to one where it was kept? |
| H18 | G7 | The Heat +FX answers the screen request (RPC framing `F0 00 20 3C 10 00`), as the Heat MKII does, so its screen can be mirrored and read without a mod. | Heat +FX, DT1, DN2 | Open Elek View (bluesgl.github.io/Elek_View) with nothing else on the MIDI port, select the unit, Start. |
| H19 | G4 | The stock start-up animation runs at 30 frames per second, so it lasts about 5.8 s (175 frames), not about 11.7 s at 15 fps (O20). | DT2, DN2 | Film a cold start with your phone, three times, and time the animation from its first frame to its last; also say whether it looked the same each time (one of five animations is picked at random, the first about 99.9 % of the time). |
| H23 | G7 | The ~4 KB cut in long MidiRpc LIST replies is in the stock reply router, not in a mod: an unpaged listing of a 256-entry table store on a modded DN2 came back as 3,997 bytes, correct up to entry 125 and garbage after; pages of 64 were clean. | DN2 | On stock, list a +Drive folder with more than 130 entries in one unpaged request (DNX or Elektroid) and compare the reply length and the tail with a paged listing. Until settled, page listings at 64 entries or fewer. |
| H6 | G8 | The DT2's SHARC DDR above the sample pool window (`0x9d22b9c8` up to `0xa0000000`, about 46 MB) is never written by stock, as the DN2's tail `0x80531000-0xa0000000` is not. | DT2 | dnfw's method: fill the range with a pattern at boot, then scan it during heavy playback, pattern and kit changes, FX extremes, sample loads and a save. Expect a reserved top part for Capicola builds only. |
| H7 | G3 | The DT2's ColdFire runs the same FreeRTOS layout as the DN2: higher priority numbers run first, prio 0 never runs, prio 1 is the idle loop; the main task's stack is barely used. | DT2 | With the USB probe: find the ready table and the running-task pointer, sample them 60 times. |
| H8 | G8 | The DN2's digikit flash cave `0x402fb7a8` (2,136 B on 1.11) keeps its bytes through a cold boot, as the DT2's `0x403117c4` does. | DN2 | A canary in the cave, read back after a cold boot and after playback. Combine with H9. |
| H9 | G8 | The DT2 flash cave `0x403117c4-0x40312000` is safe on a stock image; the freeze report (O18) came from something else in that build. | DT2 | A stock image plus a canary in the cave, read back after a cold start after a long power-off (A40). |
| H10 | G8 | DN2 L2 `0x200918c0-0x200c2000` is not written by stock in normal use (O19). | DN2 | A canary or a write watch over the range during playback, pattern changes and a save (T24). |
| H11 | G8 | DN2 RAM `0x46700000-0x46701300` is written by stock only when a +Drive transfer is over 60,672 bytes (S17: project save and load reach it). | DN2 | A canary at `0x46700000`, read back after loading a large sample or project from +Drive. |
| H12 | G3 | Direct hook writes may race reply publication on a DN2. Digikit measured 3,995 of 4,000 zero diagnostic words on a DT2; its own diagnostic clears overwrote the previous block's record in the DN2 emulator. Silicon DMA timing remains unmeasured. | DN2 | Compare a hook's direct counter writes with static-word publication at block tail, without clearing prior reply records; count arrivals on the ColdFire side. |
| H13 | G3 | SIMD loads or stores into L2 byte space hang the DN2's DSP as they hang the DT2's (same core, same IMASK). | DN2 | A one-variable probe image with one SIMD L2 access behind a key press; recovery by power cycle. |
| H14 | G3 | The SHARC's IIR0/FIR0 accelerators compute on the DT2 exactly as measured on the DN2 (output from stored word 5, FIR sums in pairs, INIDX/OUTIDX written the other way round). | DT2 | Port the accelprobe image to the DT2 and compare the 76 result words. |
| H15 | G2, G3 | On the DN2, a single late DSP block is a one-block dropout that recovers, as on the DT2; the "silence until power cycle" reports came from sustained overload. | DN2 | Provoke single late blocks (a burn loop on a key press) and count them on the DSP side; then hold an overload for seconds. |
| H16 | G1 | Heat +FX builds need a cold-start test like other ColdFire units: a startup change can pass quick restarts and fail after minutes off (A40). | Heat +FX | For the next startup-touching build: power off for 10 minutes before judging. |
| H17 | G2, G3 | Code costs on the Heat +FX follow the DT1's ColdFire lessons (EMAC mode switches, D16 hot-path hooks), since both run audio on an MCF5441x ColdFire. | Heat +FX | Measure an audio-ISR hook with and without a MACSR switch per block. |
| H20 | G8 | DT2 OS 1.17 saves only the kits the user changed, so a module's own kit data that changes by itself is lost unless a stock parameter of that kit changes too. | DT2 | Modwerk publishes a unit procedure: change only module data, save, power-cycle, reload. |
| H21 | G8 | The Octatrack stall after a PROJECT > SYSTEM walk on Modwerk builds is Modwerk's DSP stall watchdog firing while stock itself holds the frames (USB DISK MODE), not a stock fault. | Octatrack | Make the same walk on a unit with nothing installed, then with the watchdog off. |
| H22 | G1, G8 | The total freeze in octabam's demand-loader soak (I57) is the ColdFire spinning in one of the frame interrupt's waits that have no time limit, after the DSP stopped taking host words. | Octatrack | Add time limits (with a counter) to both waits and repeat the 118-switch soak. |
